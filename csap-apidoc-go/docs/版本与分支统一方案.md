## 2. 统一方案（建议）

### 2.1 一条主线

- **唯一主线：GitHub `csap-ai/csap-apidoc` 的 `main`**。Java 与 Go 都在这里开发，Go 在子目录 `csap-apidoc-go/`。
- gitee 改为**只读镜像**：先把 gitee 现有分支打成存档 tag（`archive/master`、`archive/dev`、`archive/1.0.3`、`archive/chore-apidoc-next-iteration`），再让 gitee 的默认分支跟随 GitHub `main`（两边历史不相关，gitee 的 `master` 需要强制更新，旧历史靠存档 tag 保留）。
- 本地仓库：加 GitHub 远程；本地默认分支改为跟踪 GitHub `main`。

### 2.2 分支清理

| 位置 | 处理 |
|---|---|

| GitHub `docs/version-align-1.0.0` | 关闭 PR #10 后删除 |
| gitee `master`、`dev`、`1.0.3`、`chore/apidoc-next-iteration` | 打存档 tag 后删除分支，`master` 改为 GitHub `main` 的镜像 |

| 本地 `feat/apidoc-go` | 把 4 个 Go 提交移到 GitHub `main` 上（已在临时克隆里验证：cherry-pick 无冲突，`go build`、`go test` 全部通过），之后在新分支上继续 |

### 2.3 版本号

两种选择：

- **A. 统一后的第一个版本叫 `1.1.0`（推荐）**：`1.0.0` 留给 kyty 线上那份（gitee 代码），GitHub `main` 改成 `1.1.0` 发布到 Maven Central。好处是一个版本号只对应一份代码，kyty 升级时也能看清楚是从 1.0.0 升到 1.1.0。需要改 GitHub `main` 上 pom 和文档里的版本号（上次"统一成 1.0.0"的提交要再改一次）。
- **B. 维持 `1.0.0`**：直接把 GitHub `main` 发布为 1.0.0。Central 上没有冲突，但本机和 kyty 线上的 1.0.0 是另一份代码，以后排查问题会混淆；本机 `~/.m2` 里的 1.0.0 要删掉重装。

Go 模块独立版本：在 M5 打 `csap-apidoc-go/v0.1.0`。

### 2.4 Go 版跟着调整的地方

- **对齐基准**从"gitee 生产代码"改为"GitHub `main`"。`main` 对文档协议的改动不大：`CsapDocMethod` 新增 `globalHeaderHints`、`authHint` 两个字段（新类 `CsapDocGlobalHeaderHint`、`CsapDocAuthHint`），其余 Java 改动在 UI、devtools、CI。Go 版要补上这两个字段（来源对应 `@DocGlobalHeader`、`@DocAuth`）。
- **前端**：GitHub `main` 不再提交 `csap-apidoc-ui` 的构建产物（构建时生成），Go 版的 `scripts/sync-ui.sh` 改成从 `main` 的前端源码构建（`npm ci && npm run build`）后内嵌。devtools 前端同理（M4）。
- **Java 实测比对**：之前的黄金样本来自生产 jar（= GitHub `develop`），返回过滤的语义 `main` 没有改，结论仍然有效；`/csap/apidoc` 的逐字节比对要用 `main` 构建一份重新做（会多出上面两个字段）。

## 3. 执行顺序（每一步做完再进行下一步）

1. 本地：加 GitHub 远程；把 old 的未提交改动提交到本地存档分支（不推送）。
2. 本地：从 GitHub `main` 开 `feat/apidoc-go`，移入 4 个 Go 提交；旧的 `feat/apidoc-go` 改名为 `archive/apidoc-go-on-gitee` 留作对照。
3. 版本号：按 2.3 的选择改 GitHub `main` 的 pom 和文档（单独一个 PR）。
4. **需要确认后再做**：GitHub 上推送 `feat/apidoc-go` 并开 PR；关闭 PR #10、删除 `develop` 和 `docs/version-align-1.0.0`。
5. **需要确认后再做**：gitee 打存档 tag、推送 old 存档分支、强制更新 `master` 为 GitHub `main`、删除旧分支。
6. 本地清理：删旧分支、`git worktree prune`、移除 old 工作目录、清理 `~/.m2` 里旧的 1.0.0（如选 B）。

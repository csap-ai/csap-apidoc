# 使用手册

读者:开发、维护者、只读成员。读完能查文档、看规则和历史、提修改单、审批、回滚、查审计。

管理员的事(用户、项目、令牌、Webhook、授权)见 [管理员手册](admin-guide.md)。

## 登录与导航

- 用管理员发给你的账号登录。同一账号在同一来源 IP 连续输错密码 5 次,锁定 15 分钟;同一账号 15 分钟内各 IP 合计失败 50 次也会锁定。
- 顶部菜单:**文档中心**、**规则**、**修改单**、**审计**,管理员和项目维护者还有**管理**。右上角可以修改密码、切换浅色 / 暗色、退出登录。
- 你能看到的内容由你的**项目角色**决定。没有加入任何项目的普通成员什么服务都看不到,请联系管理员。
- 页面顶部的提示条会告诉你授权状态(试用、已过期等),不影响你的日常使用。

## 你能做什么

| | 只读 | 开发 | 维护者 |
|---|---|---|---|
| 看文档、规则、历史 | ✓ | ✓ | ✓ |
| 新建、提交修改单,发起回滚 | ✗ | ✓ | ✓ |
| 审批他人的修改单 | ✗ | ✗ | ✓ |
| 查看审计 | ✗ | ✓ | ✓ |
| 导出审计 | ✗ | ✗ | ✓ |

完整权限表见 [管理员手册](admin-guide.md#角色与权限)。

## 文档中心与搜索

**文档中心**列出你有权查看的所有服务,每个服务显示语言、框架版本、实例数、状态和最近上报时间。

| 状态 | 含义 |
|---|---|
| 在线 | 服务有心跳(自动注册的服务),或最近一次拉取成功(手工添加的服务) |
| 离线 | 服务没有心跳,或拉取一直失败且没有缓存 |
| 缓存(拉取失败) | 上次拉取失败,当前显示的是上次缓存的内容 |

操作:

1. 点服务进入文档页,按接口浏览请求头、请求参数、返回字段、必填、校验规则和示例。页面上"文档拉取于"是团队版最近一次拉取的时间;团队版每 60 秒刷新一次。
2. 文档页顶部的"过滤接口"在当前服务内过滤。
3. 点"查看规则"跳到这个服务的规则页。
4. 顶部搜索框跨服务搜索:输入接口路径、标题、描述或字段名(支持中文,直接做包含匹配),回车或点"搜索"。结果最多 100 条,每条标出命中的位置(路径、标题、描述、字段)。可以先用项目下拉框缩小范围。

搜索只覆盖你有权看的服务。

## 规则查看与历史对比

**规则**页(菜单"规则")选择服务后,左边列出这个服务的规则条目:规则 key、当前版本、更新人、更新时间。

- **查看**:显示这条规则当前的 JSON。已删除或没有规则时显示"(已删除 / 无规则)"。
- **历史**:显示这条规则的每次修改:版本、更新人、时间、修改前后的内容。历史来源有两种:
  - "修改单 #n":通过团队版发布;
  - "服务侧直接修改":有人在服务自己的 DevTools 里改了规则,团队版同样会记录。
- **对比两版**:选"起点版本"和"终点版本"(终点可选"当前"),显示统一差异,可切换"统一视图"和"并排视图"。
- **修改此规则**(开发、维护者):带着这条规则去新建修改单。

规则 key 的形式由服务语言决定:Java 是 `类全名.方法名`,Go 是 `分组.接口名`。

## 修改单

团队版里**所有规则改动都走修改单**:先写草稿,提交,按项目设置审批,通过后发布到数据库,服务在几秒内热更新。

### 流程

```
草稿 ──提交──▶ 待审批 ──通过并发布──▶ 已发布
 │               ├──驳回──▶ 已驳回
 │               └──撤回──▶ 已撤回
 ├──撤回──▶ 已撤回
 └──提交时或审批时版本已过期──▶ 冲突 ──更新到最新版本──▶ 草稿
```

项目如果在设置里**关闭了"需要审批"**,提交后直接发布(仍然记审计,仍可回滚),页面会提示"该项目无需审批,已直接发布"。

### 新建草稿

1. 菜单"修改单"→"新建修改单"(或在规则页点"修改此规则")。
2. 选择项目,填**标题**(不超过 256 字)和**修改原因**。
3. 点"添加规则条目",选服务、填接口 / 规则 key。点"载入当前规则"把库里现在的内容带进来,再编辑"修改后的规则 JSON"。可以点"格式化"整理 JSON。
4. 要删除一条规则,勾选"删除该规则(置空)"。
5. 一张修改单至少 1 条、最多 500 条规则;同一张单里不能重复同一条规则;所有条目的服务必须属于所选项目。
6. 保存即得到**草稿**。草稿只有作者能编辑和提交。

规则 JSON 的写法与开源版的字段规则相同,见开源文档"字段规则"。内容不是合法 JSON 时保存会报错。

### 提交

在草稿详情页点"提交"。

- 提交时系统会检查一次版本:如果规则在你写草稿之后被别人改过,修改单直接变成"冲突",避免审批人白审。
- 通过检查后进入"待审批",并通知(如果配置了 Webhook)。
- 只有作者能提交。

### 审批、驳回

维护者(和管理员)在待审批的修改单里看每条规则的**差异**,然后:

- **通过并发布**:可填审批意见。发布时会再检查一次版本,同一事务里写入数据库。
- **驳回**:必须填写意见。

规则:

- 维护者**不能审批自己提交的**修改单(按钮会被禁用并说明原因)。
- 管理员可以审批自己的(小团队需要),审计里照常记录。
- 内容与库里完全相同的条目发布时会被跳过,不算冲突,也不产生新版本。

### 撤回

草稿和待审批的修改单可以撤回,作者、该项目维护者和管理员都可以操作。撤回后状态为"已撤回",不能再恢复,需要重新建单。冲突状态的修改单只能由作者"更新到最新版本"。

### 冲突与"更新到最新版本"

别人(或服务自己的 DevTools)在你的修改单之后改了同一条规则,你的修改单基于的版本就过期了,状态变为"冲突"。修改单详情页会显示:

- 每条冲突规则的"基线版本 → 当前版本";
- 左边"我的修改",右边"当前库里的内容";
- "差异(当前库 → 我的)"。

处理:

1. 作者点**更新到最新版本**。
2. 对每条规则选择"采用当前库内容"或"保留我的内容",也可以直接改。
3. 确认后,修改单以当前库内容为新的基线,状态回到**草稿**。
4. 检查后重新提交。

只有作者可以执行"更新到最新版本"。冲突的修改单不能直接审批。

### 查看修改单

"修改单"列表可以按状态、项目筛选,勾选"仅看我的"只看自己的。详情页显示流程时间线(提交、审批人、审批意见、发布时间)和每条规则的差异。类型"回滚"表示这张单是由回滚生成的。

## 回滚

回滚也走修改单,**不是直接改库**。

1. 在"规则"页选服务和规则,打开"历史"。
2. 在要回到的那个版本上点"回滚到此版本"。
3. 填回滚原因,确认。系统生成一张类型为"回滚"的修改单(草稿),内容为那个版本修改后的规则;如果那次修改是删除,回滚就是删除。
4. 到这张修改单上点"提交",后面和普通修改单一样(项目需要审批就等审批)。

发起回滚需要开发及以上角色;服务必须已经归属某个项目。

## 审计查询与导出

菜单"审计"有两个标签:**操作记录**和 **MCP 调用**。

### 操作记录

记录每次写操作:登录成功 / 失败、用户、成员、项目、服务、令牌、Webhook、授权的变更,修改单的创建、编辑、提交、审批、驳回、撤回、发布、冲突、更新到最新版本,服务侧直接改规则,以及导出审计本身。

筛选条件:时间段、操作人、服务、接口(规则 key)、动作、来源,分页显示。点一条记录看详情:修改前、修改后、差异和原因。

"来源"的含义:

| 来源 | 说明 |
|---|---|
| 控制台 | 在网页里的操作 |
| 开放接口 | 脚本用令牌调用 |
| 服务侧修改 | 有人在服务自己的 DevTools 里直接改了规则 |
| MCP | MCP 相关记录 |
| 系统 | 系统自动动作,例如审计保留期清理 |

说明:

- 审计**只追加**,界面和接口都没有修改、删除审计的入口。唯一的删除是管理员配置的保留期清理,而且清理本身会记一条"清理审计"。
- "动作"筛选框填动作代码,精确匹配;以 `*` 结尾时按前缀匹配,例如 `change.*` 查所有修改单相关动作,`change.publish` 只查发布。
- "服务侧修改"的记录在服务改完后约十几秒内出现,操作人是该次修改记录里的更新人。
- 你只能看到所在项目的记录。开发角色只能查看,**维护者和管理员**可以导出。

### 导出

筛选之后点"导出 CSV"或"导出 JSON"(维护者及以上)。

- CSV 使用 UTF-8 带 BOM,Excel 直接打开不乱码。以 `=`、`+`、`-`、`@` 开头的内容会加一个前导 `'`,防止在 Excel 里被当作公式执行。
- 一次最多导出 100,000 条,流式下载。超过时缩小时间段分批导出。
- 导出动作本身会被记审计。

### MCP 调用

"MCP 调用"标签显示服务端 MCP 工具被调用的记录:服务、时间、调用方(令牌名)、来源地址、工具、目标接口、参数摘要、结果摘要、成功与否、耗时。可按服务、时间、调用方、工具筛选,同样支持导出(维护者及以上)。

参数和结果都是服务端脱敏、截断后的摘要。

如果显示"服务未开启 MCP 审计落库",说明还没有服务把 MCP 审计写进数据库,请联系服务的开发者按 [服务接入](connect-services.md#mcp-调用审计落库java) 配置。

## 常见问题

| 问题 | 回答 |
|---|---|
| 看不到某个服务 | 服务没有归属你所在的项目;未归属项目的服务只有管理员能看 |
| 提交修改单提示冲突 | 规则已被别人改过,按上文"更新到最新版本"处理 |
| "通过并发布"点不了 | 维护者不能审批自己提交的修改单,请其他维护者或管理员审批 |
| 发布后服务没变化 | 服务按数据库版本号轮询(默认约 5 秒);等一会儿。仍不生效,联系管理员确认服务和团队版连的是同一个库、同一个表前缀 |
| 提示"登录已失效" | 会话 12 小时无操作后过期,重新登录 |
| 审计页没有导出按钮 / 导出灰色 | 你的角色是开发或只读,只有维护者和管理员能导出 |

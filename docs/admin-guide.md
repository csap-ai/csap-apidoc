# 管理员手册

读者:组织管理员、项目维护者。读完能建用户和项目、分配角色、管理令牌和 Webhook、上传授权、设置审计保留期。

控制台菜单"管理"下有六个标签:**项目与成员**、**服务归属**、**用户**、**令牌**、**Webhook**、**授权**。管理员能看到全部;项目维护者只能看到前三个(项目与成员、服务归属、Webhook),并且只能操作自己项目的内容。其他角色看不到"管理"菜单。

## 角色与权限

团队版有两层角色:

- **组织角色**:`管理员`或`普通成员`。管理员拥有全部权限,在所有项目里等同维护者。1.0 是单组织。
- **项目角色**:`维护者`、`开发`、`只读`。一个用户可以在不同项目里有不同角色。

| 能力 | 管理员 | 维护者 | 开发 | 只读 |
|---|---|---|---|---|
| 看文档中心、规则、历史 | 全部服务 | 所在项目 | 所在项目 | 所在项目 |
| 建草稿、提交修改单 | ✓ | ✓ | ✓ | ✗ |
| 审批(通过 / 驳回) | ✓ | ✓(不能审批自己提交的) | ✗ | ✗ |
| 回滚(发起回滚修改单) | ✓ | ✓ | ✓(同样走审批) | ✗ |
| 查审计 | 全部 | 所在项目 | 所在项目 | ✗ |
| 导出审计 | ✓ | 所在项目 | ✗ | ✗ |
| 项目成员管理 | ✓ | ✓(不能设置或移除管理员) | ✗ | ✗ |
| 项目设置(是否需要审批)、服务归属 | ✓ | ✓ | ✗ | ✗ |
| Webhook | ✓ | 所在项目 | ✗ | ✗ |
| 新建项目、删除项目 | ✓ | ✗ | ✗ | ✗ |
| 用户、令牌、授权 | ✓ | ✗ | ✗ | ✗ |

补充规则:

- 管理员审批自己提交的修改单是允许的(小团队需要),审计里照常记录。
- 没加入项目的人看不到该项目的服务、修改单和审计。访问不属于自己的内容返回"不存在",不暴露存在性。
- 项目关闭"需要审批"后,提交即发布。

## 用户

"管理 → 用户"(仅管理员)。

| 操作 | 说明 |
|---|---|
| 新建用户 | 填账号、姓名、初始密码、组织角色 |
| 重置密码 | 管理员为用户设置新密码;用户的旧会话随即失效 |
| 停用 / 启用 | 停用后该用户无法登录,已登录的会话立即失效;数据和审计保留 |
| 改组织角色 | 管理员 / 普通成员 |

规则:

- 账号只能含字母、数字和 `.` `_` `@` `-`,长度 2–64;登录锁定时账号不区分大小写。
- 密码至少 8 位,最多 72 字节。
- **不能停用或降级最后一个管理员**。
- 新建或启用用户时,**活跃用户数不能超过授权人数**;超过会提示"活跃用户已达授权上限"(错误码 `LICENSE_LIMIT`)。停用用户不占名额。
- 用户自己可以在右上角"修改密码"。修改后其他设备上的会话失效。
- 登录失败锁定:同一账号 + 同一来源 IP 连续失败 5 次锁 15 分钟;同一账号 15 分钟内所有 IP 合计失败 50 次也锁定 15 分钟。重启团队版会清零。

## 项目与成员

"管理 → 项目与成员"。

### 项目

- 新建项目(仅管理员):名称(唯一,不超过 128 字)和说明。
- 项目设置:**需要审批**开关。打开(默认)时,修改单要有维护者或管理员通过才发布;关闭后提交即发布。关闭审批的项目仍然记审计、仍可回滚。
- 删除项目(仅管理员):项目下没有服务时才能删除,有服务要先移走或删除。

### 成员

1. 选中项目,在"成员"里点"添加成员"。
2. 选用户和角色(维护者 / 开发 / 只读)。候选列表只显示还不在本项目、且已启用的用户。
3. 改角色:在成员行里直接改;移除:点移除。

规则:

- 管理员和项目维护者可以管理成员;维护者**不能设置或移除管理员的项目角色**。
- 一个用户在一个项目里只有一个角色。
- 建议每个项目至少有两个维护者,避免维护者提交的修改单没人能审批(管理员除外)。

### 服务归属

"管理 → 服务归属"列出所有服务(管理员)或你的项目的服务(维护者):

- 点"分配到项目",或改所属项目。改归属需要同时是原项目和目标项目的维护者(管理员不受限);把服务改成"未分配"只有管理员能做。
- "未分配的注册服务"只有管理员能看到。
- 手工添加和删除服务见 [服务接入](connect-services.md#手工添加服务)。删除服务只是从团队版目录里移除,不会删除数据库里的规则。

## 令牌

"管理 → 令牌"(仅管理员)。令牌用于服务注册和脚本调用开放接口。

| 用途 | 能做什么 |
|---|---|
| `REGISTER`(服务注册) | 服务注册、心跳、注销 |
| `OPEN_API`(规则读写) | 读规则、创建(并可提交)修改单;**不能审批** |

- 创建时可以限定项目。限定后,令牌只能操作该项目的服务。
- **令牌明文只在创建时显示一次**,格式 `csapt_` 加 40 位随机字符。团队版只保存哈希和前 8 位前缀。
- 列表显示名称、前缀、用途、限定项目、创建人、最近使用时间、是否已撤销。
- 撤销后令牌立即失效,不可恢复。
- 令牌的使用者记为令牌创建者(审计"操作者类型"为令牌,显示令牌名称)。创建者被停用后,令牌调用失败。
- 令牌要放在环境变量或密钥管理里,不要提交到代码仓库。

## Webhook

"管理 → Webhook"。管理员可以建作用于全部项目的 Webhook;项目维护者可以给自己的项目建。

### 配置项

| 字段 | 说明 |
|---|---|
| 名称 | 不超过 128 字 |
| 类型 | 通用 Webhook / 企业微信 / 钉钉 / 飞书 |
| 地址 URL | `http` 或 `https` |
| 密钥 Secret | 可选,不超过 256 字。**只写不回显**,编辑时留空表示不修改 |
| 订阅事件 | 至少选一个,见下表 |
| 项目 | 限定项目,或"全部项目"(仅管理员) |
| 启用 | 开关 |

### 事件

| 事件 | 何时触发 |
|---|---|
| `change.submitted` | 修改单提交 |
| `change.approved` | 修改单通过 |
| `change.rejected` | 修改单驳回 |
| `change.published` | 修改单发布 |
| `change.conflict` | 修改单冲突 |
| `rule.changed_outside` | 有人在服务侧(DevTools)直接改了规则 |
| `service.offline` | 服务离线(同一服务 10 分钟内只发一次) |

### 投递与重试

- 异步发送,不阻塞业务;单次请求超时 10 秒。
- 失败自动重试 3 次,间隔 10 秒、60 秒、300 秒(可用 `csap.team.webhook.retry-delay-seconds` 调整)。
- 每次投递(含重试)都记录一条:事件、时间、第几次、成功或失败、HTTP 状态、错误信息。每个 Webhook 保留最近 1000 条。
- 点"发送测试"同步发一条测试消息(不重试),并返回这次投递结果;点"投递记录"查看历史。
- 作用于"全部项目"的 Webhook 会收到所有项目的事件,也是唯一能收到未归属项目的服务离线通知的 Webhook;限定项目的只收该项目的事件。
- 通知里的"修改单链接"来自 `csap.team.public-url`,没配置时通知不带链接。

### 通用 Webhook

请求:`POST`,`Content-Type: application/json`,请求头带:

| 请求头 | 说明 |
|---|---|
| `X-CSAP-Team-Event` | 事件名,如 `change.published` |
| `X-CSAP-Team-Signature` | 仅在配置了 Secret 时带:`sha256=<十六进制>`,值是用 Secret 对**原始请求体**做 HMAC-SHA256 |

请求体示例:

```json
{"event":"change.published","at":1763452800000,"project":{"id":1,"name":"订单"},
 "change":{"id":12,"title":"调整下单金额校验","author":"张三","url":"https://team.example.com/changes/12"},
 "items":[{"service":"order-service","ruleKey":"demo.OrderController.create"}],
 "text":"[订单] 张三 的修改单「调整下单金额校验」已发布(1 条规则)"}
```

`change` 对没有修改单的事件(如服务离线)不出现或为空;`change.url` 仅在配置了 `public-url` 时出现。

**接收方必须校验签名**,并用**原始字节**计算,不要先解析再重新序列化。

Python(Flask)示例:

```python
import hmac, hashlib
from flask import Flask, request, abort

SECRET = b"<你在团队版里填的 Secret>"
app = Flask(__name__)

@app.post("/hook")
def hook():
    body = request.get_data()                      # 原始请求体
    expected = "sha256=" + hmac.new(SECRET, body, hashlib.sha256).hexdigest()
    given = request.headers.get("X-CSAP-Team-Signature", "")
    if not hmac.compare_digest(expected, given):   # 常量时间比较
        abort(401)
    event = request.headers.get("X-CSAP-Team-Event")
    # ... 处理 event、request.get_json()
    return "", 204
```

Node.js(Express)示例:

```js
const crypto = require("crypto");
const express = require("express");
const app = express();
const SECRET = "<你在团队版里填的 Secret>";

app.post("/hook", express.raw({ type: "application/json" }), (req, res) => {
  const expected = "sha256=" + crypto.createHmac("sha256", SECRET).update(req.body).digest("hex");
  const given = req.get("X-CSAP-Team-Signature") || "";
  const ok = given.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(given), Buffer.from(expected));
  if (!ok) return res.sendStatus(401);
  // ... 处理 req.get("X-CSAP-Team-Event")、JSON.parse(req.body)
  res.sendStatus(204);
});
```

接收方返回 2xx 视为成功,其他状态码或超时会重试。

### 企业微信

1. 在企业微信群里添加"群机器人",复制 Webhook 地址(形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<机器人 key>`)。
2. 团队版新建 Webhook,类型选"企业微信",粘贴地址,选择事件。
3. Secret 留空(企业微信群机器人不使用签名)。
4. 点"发送测试",群里应收到一条 Markdown 消息。

### 钉钉

1. 在钉钉群里添加"自定义机器人",安全设置选**加签**,记下 `SEC` 开头的密钥;复制 Webhook 地址(形如 `https://oapi.dingtalk.com/robot/send?access_token=<令牌>`)。
2. 团队版新建 Webhook,类型选"钉钉",粘贴地址,在 Secret 里填加签密钥。
3. 团队版会按钉钉规则在地址后附加 `timestamp` 和 `sign`。
4. 点"发送测试"验证。

不要用"自定义关键词"作为钉钉的安全设置:消息不一定含你设置的关键词。推荐加签或 IP 白名单。

### 飞书

1. 在飞书群里添加"自定义机器人",复制 Webhook 地址(形如 `https://open.feishu.cn/open-apis/bot/v2/hook/<机器人标识>`)。
2. 如开启了**签名校验**,记下签名密钥。
3. 团队版新建 Webhook,类型选"飞书",粘贴地址;开启了签名校验时在 Secret 里填密钥。
4. 点"发送测试"验证。

三个平台的回调如果返回了平台错误(例如签名不对、关键词不匹配),投递记录里会写成失败并带上平台的错误信息。

Webhook 地址里常带机器人的凭据(`key`、`access_token`)。界面和接口只显示协议和主机,其余部分隐藏;编辑时 URL 留空表示不变,Secret 同样只写不回显。数据库里的地址和密钥是明文存储,请限制数据库访问权限。

## 授权文件

团队版按**活跃用户数**授权。

| 状态 | 含义 | 影响 |
|---|---|---|
| 试用 | 没有授权文件 | 最多 5 个活跃用户,界面顶部提示 |
| 有效 | 签名正确,未过期 | 活跃用户数上限 = 授权人数 |
| 已过期 | 签名正确,已过期 | **已有数据和功能不锁**,只限制新增或启用用户,上限回到试用的 5 人 |
| 无效 | 签名校验失败或格式错误 | 按试用处理 |

要点:

- 活跃用户 = 状态为"正常"的用户。停用用户不占名额。
- 过期后已有用户照常登录、照常使用;只是新建或启用用户时,如果现有活跃用户已达到 5 人,会被拒绝。
- 授权到期时间按 UTC 当天结束计算。

### 上传授权

方式一:控制台(推荐)。

1. "管理 → 授权",点"上传授权"。
2. 粘贴授权文本,或选择授权文件,点"提交授权"。
3. 页面显示授权对象、人数上限、活跃用户、到期时间。

上传的授权存在数据库里,优先于配置文件。授权文本签名无效时会被拒绝,原授权不变。

方式二:配置文件。把授权文件放到服务器上,配置 `csap.team.license-file=/etc/csap-team/team.lic`(或环境变量 `CSAP_TEAM_LICENSE_FILE`),启动时读取。没有在控制台上传过授权时才使用它。

授权文件由发行方签发,向你的供应商获取。更换授权(扩容、续期)直接再上传一次即可,无需重启。

## 审计保留期

默认永久保留全部审计。要限制保存时间,设置:

```bash
export CSAP_TEAM_AUDIT_RETENTIONDAYS=365      # 保留 365 天,0 = 永久
```

或 `csap.team.audit.retention-days: 365`。

- 清理任务每小时运行一次(启动一分钟后第一次),删除早于保留期的审计。
- 清理会记一条"清理审计"记录,写明保留期和清理条数。这是代码里**唯一**会删除审计的地方。
- 清理前如需留底,先用审计页的导出保存。
- MCP 调用记录不由团队版清理,它们在服务的数据库表里,由服务端的 `csap.apidoc.mcp.audit.max-rows` 控制。

## 日常运维清单

| 周期 | 事项 |
|---|---|
| 每次人员变动 | 停用离职人员;调整项目成员角色 |
| 每季度 | 检查令牌列表,撤销不再使用的令牌;检查每个项目至少两名维护者 |
| 授权到期前 | 联系供应商续期并上传 |
| 每天 | 数据库备份(见 [部署与运维](install.md#备份与恢复)) |
| 按需 | 导出审计留档;查看 Webhook 投递记录里有无连续失败 |

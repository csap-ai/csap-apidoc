# CSAP Apidoc 产品路线图

> 2026-11-17 审定,2026-11-19 随 1.5.0 与团队版 1.0.0 发布更新,2026-11-27 随团队版 1.1.0 发布更新。官网"路线图"页与本文件同步。
> 原 `csap-apidoc-devtools/APIDOC开发工具产品路线图.md`(2025-10,含"商业化策略"和示例性的版本记录)由本文件取代。

## 1. 定位

**CSAP Apidoc 是一个多语言的运行时 API 文档框架。** 服务启动时直接从代码生成文档,按接口控制显示哪些字段,页内在线调试;同一份文档同时提供给人(文档页面)和 AI(MCP)。

三样东西跨语言共用,这是"多语言"成立的基础:

| 共用部分 | 内容 | 现状 |
|---|---|---|
| **文档协议** | `/csap/apidoc*` 接口的 JSON 结构 | Java 定义;Go 已逐字节兼容 |
| **规则格式** | `<Controller>-method-field.yaml`(请求参数、返回字段、校验规则) | Java 定义;Go 已兼容,可直接复用 Java 项目的文件 |
| **前端** | 文档页面 `csap-api.html`、后台 DevTools | 只写一份,各语言内嵌同一份构建产物 |

所以新增一门语言 = 实现"扫描代码 → 输出协议 → 读规则",前端、MCP、团队版自动可用。

## 3. 版本规划

**版本号规则:从 1.6.0 起,Java、Go、团队版统一用一个版本号**,一起发布、持续迭代。每个版本一个 GitHub Release `vX.Y.Z`(说明分 Java / Go / 团队版三段,附团队版 jar);Go 模块在子目录里,tag 仍须写成 `csap-apidoc-go/vX.Y.Z`(号码相同,Go 从 v0.3.x 直接到 v1.6.0)。某次只改了其中一部分时,其余部分也同号发布,说明里写"无变化"。1.6.0 之前三者各自编号(Java 1.x、Go v0.x、团队版 1.0–1.1)。

### 1.1.1 — 补丁(已发布,2026-11-17)

- 所有模块编译为 Java 11 字节码(1.1.0 实际是 Java 17 字节码)
- 只引入文档 starter 即可使用(修空指针)
- 文档页面按源码构建,发布流程自动构建前端
- 在线调试按 `@DocGlobalHeader` / `@DocAuth` 预填请求头和鉴权
- 修:缓存被 `?key=` 改坏、`flush` 无效、YAML/JSON 文档策略未注册、SQLite 自动建库、Spring Boot 3 下 DevTools 代理、默认 HTTP 方法、内置正则、Postman 导出;前端配置导出明文泄露密钥(安全)等
- CI 真正执行测试;示例工程可以直接运行

### 1.2.0 — 运行时能力补全 + Go 版首发(已发布,2026-11-17)

- **返回字段过滤**、**请求参数校验**作为独立模块重新提供(不依赖 csap-framework),Spring Boot 2 / 3 都支持;校验支持"观察模式"(只记录不拦截)
- 暗黑模式(本版只覆盖文档页,DevTools 后续版本补上)
- **Go 版 v0.1.0**:在 M1–M3 基础上完成 M4(后台管理、修改记录与回滚、鉴权)和 M5(net/http 适配、Postman 导出)。发布方式:GitHub tag `csap-apidoc-go/v0.1.0`,`go get github.com/csap-ai/csap-apidoc/csap-apidoc-go@v0.1.0`
- 修 1.1.1 遗留:OpenAPI 导出的空指针、JSON 策略写出的文件格式、旧 SQLite 库的约束迁移

### 1.3.0 — 文档即 MCP(已发布,2026-11-18)

让 AI 智能体直接"读懂并调用"你的接口,不用另写一层。

**形态:内嵌在服务里,按需开启,不需要另起服务。**

- **内嵌 MCP 端点**:服务自身提供 `/csap/mcp`(Streamable HTTP),**默认关闭**,配置 `csap.apidoc.mcp.enabled: true` 开启。每个接口自动转成一个 MCP 工具:工具名、说明、参数 JSON Schema 都来自文档;返回字段按规则过滤。
- **后台管理**:在 DevTools 里新增"MCP"页面:
  - 勾选哪些接口暴露给 AI(默认只勾选 GET,写操作需要逐个打开)
  - 每个工具的名称、说明可以单独改写,让 AI 更好理解
  - 鉴权方式:透传调用方的请求头,或使用为 MCP 单独配置的令牌
  - 调用审计日志:谁、什么时间、调了哪个工具、参数和结果摘要
  - 配置保存到规则文件(YAML / SQLite),和字段规则一样可以版本管理
- **独立聚合服务(可选)**:`csap-apidoc-mcp` 进程,同时指向多个服务(不限语言)的 `/csap/apidoc`,对 AI 提供一个统一入口;支持 stdio(本地 AI 编辑器)和 Streamable HTTP。适合网关或多服务场景;单个服务直接用内嵌端点即可。
- **Agent Skill**:`csap-apidoc` 技能**首版已提供**(`skills/csap-apidoc/`);1.3.0 加入通过 MCP 查询和调试接口的用法。技能随仓库维护、随版本更新。
- 1.3.0 之前发布**协议规范**和**一致性测试套件**(见"多语言")。

### 1.4.0 — 设计与协作基础(已发布,2026-11-18,原计划 12-22)

Java 1.4.0 与 Go v0.2.0 同时发布。实际交付:

- **[数据库模式](https://apidoc.csap.ai/guide/database-mode)**:字段规则存进业务已有的 **MySQL / PostgreSQL / 达梦(DM8)/ 人大金仓(KingbaseES)**,默认使用应用自己的 DataSource;多实例几秒内同步(轮询版本号),每次修改留记录、可在 DevTools「规则记录」页对比和回滚,可设只读模式。**Java 与 Go 共用同一套表**(Go 随 v0.2.0 升级表结构,提供 v0.1.x 旧表迁移)。限制:达梦、人大金仓**没有在真实数据库上验证**,属于试用。
- **[Redis 模式](https://apidoc.csap.ai/guide/redis-mode)**:规则存进 Redis,订阅变更即时同步,修改记录保留最近若干条;Java 与 Go 同一种数据结构。限制:Redis Cluster、哨兵、认证没有实测。
- **迁移工具**(`csap-apidoc-migrate`、Go 的 `strategy.Import`):YAML / SQLite → 数据库 / Redis,数据库 / Redis → YAML 导出;默认不覆盖,可演练,修改人 `migrate`、可回滚。限制:不搬运字段库的项目模板。
- **[Mock 服务](https://apidoc.csap.ai/guide/mock)**:按文档生成可复现的模拟数据(`/csap/mock/{原路径}`),默认关闭;规则里可指定 `mock` 值。Java 与 Go。
- **[JSON Schema 导入导出](https://apidoc.csap.ai/guide/json-schema)**:导出全部或单个接口的 Schema(2020-12);导入只更新已有字段的说明、必填、示例、校验,默认只预览、端点默认关闭。
- **[字段库与模板](https://apidoc.csap.ai/guide/field-library)**:16 条内置模板 + 项目模板,在 DevTools 里套用。
- **[版本对比与破坏性变更检测](https://apidoc.csap.ai/guide/api-diff)**:Go 命令行工具 `csap-apidoc-diff`,可放进 CI,Java 与 Go 服务的文档都能比。
- **[接口上下线管理](https://apidoc.csap.ai/guide/api-status)**:`ApiStatus` 在文档页、OpenAPI、MCP(默认隐藏过时接口)和 DevTools 里生效。
- **Java 与 Go 的校验行为对齐**(**以 Go 为准**):非必填字段传了值就校验;Java 的行为变化,可用 `csap.validation.optional-field-rules=skip` 恢复旧行为;Java 与 Go 共用 71 条黄金用例。
- **Go 响应体过滤**:`ShouldFilterBody`、`SuccessField`,业务失败也返回 200 的项目不再裁剪失败体。

数据库模式的设计见 [database-mode.md](https://github.com/csap-ai/csap-apidoc/blob/main/docs/design/database-mode.md)。

### 2.0(不兼容变更)

- 删除 `@Group` / `@Request` / `@Response` 与 `@ApiModelProperty.groups`(1.3.0 起弃用),按接口选择字段改用 YAML / SQLite 规则,全局显示用 `forceReq` / `forceRep`
- 删除方法级 `@ApiProperty` / `@ApiPropertys`(1.3.0 起弃用,早已不读取),改为标在参数上

### 多语言

按主流程度依次支持。每一门语言都实现同一份协议、读同一种规则文件、内嵌同一个文档页面。

| 顺序 | 语言 | 计划 | 首批适配框架 |
|---|---|---|---|
| — | Java | 已发布 | Spring Boot 2.x / 3.x(Spring MVC) |
| — | Go | v0.1.0 已于 2026-11-17 发布(当前 v0.3.0) | gin、net/http;echo、chi、fiber 随后 |
| 1 | Rust | 2027 Q1 | axum、actix-web |
| 2 | Python | 2027 Q1–Q2 | FastAPI、Flask |
| 3 | Node.js / TypeScript | 2027 Q2 | NestJS、Express |
| 4 | Kotlin、C#、PHP 等 | 之后按社区需求 | Ktor、ASP.NET Core、Laravel |

为了让各语言长期一致,1.3.0 前先发布:

- **协议规范**:`/csap/apidoc*` JSON 结构、规则 YAML 格式、过滤与校验语义的正式文档(现在是"以 Java 实现为准")。
- **一致性测试套件**:一组标准输入和期望输出(黄金样本),任何语言的实现跑通即视为兼容。Go 版已经用这种方式对齐了 Java。

### 团队版 1.0(已发布,2026-11-19,原计划 12-31)

面向多服务、多成员的团队,把分散在各服务里的文档集中管理。

**形态**:免费开源(Apache-2.0),和开源版在同一个仓库(`csap-apidoc-team/` 目录),企业自己部署(Docker / jar),不限人数、不需要授权文件。单服务用开源版本身即可,团队版只做多人、多服务的事。

首版(1.0.0)交付:

- **文档中心**:汇聚多个服务(不限语言)的文档,统一搜索、统一入口(现有网关聚合的升级版)
- **基于数据库模式**:规则、修改记录、审计都存在企业自己的 MySQL / PostgreSQL / 达梦 / 人大金仓里
- **成员与角色**:组织、项目、成员;管理员 / 维护者 / 开发 / 只读四种角色
- **多人协作**:修改先存草稿;提交时按版本号检测冲突,不会互相覆盖;维护者审批后才发布(可按服务、环境配置是否需要审批)
- **审计追溯**:每次操作记录谁、何时、从哪里(DevTools / MCP / 开放接口 / 迁移工具、来源 IP)、改了什么(前后内容与差异)、为什么(提交说明、审批单);规则完整历史,任意版本对比与回滚;按人 / 时间 / 服务 / 接口查询,导出 CSV / JSON 满足内控与等保留存;MCP 调用审计汇总在同一界面
- **变更通知**:Webhook(企业微信、钉钉、飞书可直接接入)
- **服务接入**:Java `csap-apidoc-team-client`、Go `team` 包自动注册与心跳

限制:Docker 镜像已在 PostgreSQL 16、MySQL 8 上验证;达梦、人大金仓**没有在真实数据库上验证**。单实例部署。

### 团队版 1.1(已发布,2026-11-27,原计划 2027 Q1)

- **多环境**:开发 / 测试 / 生产等环境在配置里定义,各用自己的数据库;服务、令牌、文档、修改单、审计按环境区分;受保护环境的发布一律要审批
- **环境差异对比与一键推广**:推广生成修改单,走原有的审批、冲突检测与回滚
- **评论与编辑中提示**:修改单评论;编辑规则时提示谁也在编辑、有哪些未完成的修改单
- **审计哈希链**:审计记录防篡改,控制台一键校验,附离线校验脚本

限制同 1.0:达梦、人大金仓的建表与升级脚本**没有在真实数据库上验证**;单实例部署。

之后(2027):

- 细粒度权限(谁能看哪些接口、谁能改规则)
- SSO:OIDC、LDAP
- API 监控与分析:调用量、错误率、慢接口
- 跨服务的版本发布记录、破坏性变更告警
- AI 辅助:AI 生成测试用例、根据代码变更建议文档更新、团队共享的 MCP 网关

## 5. 已确定的决策(2026-11-17)

1. **时间**:开源版 1.2.0–1.5.0 与团队版 1.0.0 都在 2026 年 11 月发布,日期见第 3 节。
2. **团队版**(2026-11-19 修订):免费开源(Apache-2.0),并入本仓库 `csap-apidoc-team/` 目录,企业自部署,不设授权机制。原定的"商业授权、独立私有仓库"取消。
3. **语言顺序**:按主流程度,Rust → Python → Node.js / TypeScript → 其他。
4. **MCP**:内嵌在服务中,默认关闭、按需开启;默认只暴露 GET;在 DevTools 后台管理暴露范围、鉴权和审计。
5. **官网**:以文档完整为重点,覆盖接入开发、文档使用团队、管理运维三类读者;规划内容只在路线图页。
6. **数据库模式**(2026-11-18):1.4.0 支持把规则存进 MySQL、PostgreSQL、达梦、人大金仓,以及 Redis,Java 与 Go 共用同一套表;团队版在此基础上做多人协作(草稿、冲突检测、审批)和审计追溯。
7. **弃用**(2026-11-18):`@Group` / `@Request` / `@Response` / `groups` 与方法级 `@ApiProperty` / `@ApiPropertys` 在 1.3.0 标为弃用,2.0 删除。

## 6. 原则

- 官网、README 只把**已发布**的功能当作功能介绍;规划中的内容只出现在路线图,明确标注。
- 每个版本发布前,文档按代码核对一遍。
- 各语言实现以协议规范和一致性测试为准,不以某一种语言的实现为准。

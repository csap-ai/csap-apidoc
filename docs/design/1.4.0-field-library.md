# 字段库与模板

状态:约定草案,待审。把常用字段(说明、示例、校验规则)做成**模板**复用,扩展现有的内置正则模板。本文定:模板的格式(YAML,Java / Go 共用)、存放位置、DevTools 里怎么套用、模板更新后已套用的字段怎么办。

## 1. 现状与要解决的问题

- 现有“模板”只有内置正则:Java `ValidatePatternType`(`PATTERN_00` ~ `PATTERN_nn`,每条是说明 + 正则 + 类型),Go `validate.Patterns` 是它的对应(Go 修正了几条写错的正则)。DevTools 的“校验规则”弹窗里勾选后会加一条 `Pattern` 规则。
- 一个字段通常要同时配**说明、示例、必填、一组校验规则**(例如“手机号”:说明“手机号”、示例 `13800138000`、Pattern `PATTERN_35`、提示“手机号格式不对”)。现在每个接口的每个字段都要重复配一遍,团队里写法也不一致。
- 要的是:把这一整套存成模板,在任何接口的任何字段上一键套用。

## 2. 模板格式(YAML)

```yaml
version: 1
templates:
  - name: phone-cn            # 唯一标识:小写字母、数字、- _,最长 64
    title: 手机号(中国大陆)    # 列表里显示的名字
    category: 通用             # 分组,可选
    description: 手机号        # 套用到字段的说明,可选
    example: "13800138000"    # 示例,可选(注意加引号,避免被当成数字)
    required: false           # 套用时是否改变必填,可选;不写表示不改
    validate:                 # 校验规则,可选;结构与规则 JSON 的 validate 项一致
      - type: Pattern
        pattern: PATTERN_35   # 内置正则名或正则本身
        code: "400"
        message: 手机号格式不对
        level: 1
```

| 字段 | 必须 | 说明 |
|---|---|---|
| `version` | 是 | 文件格式版本,目前 `1`;读到更高版本时忽略整个文件并警告 |
| `templates[].name` | 是 | 唯一标识;同一来源内重复时后者覆盖前者并警告 |
| `title` | 是 | 显示名 |
| `category`、`description`、`example`、`required`、`validate` | 否 | 套用到字段的内容,字段与规则里同名项一致 |

- **不包含参数位置**(`paramType`:query / body / header 属于接口,不属于字段通用的内容)和**返回字段是否输出**(`include`)。
- `validate` 项的 `type` 只用两种语言共有的:`NotNull`、`NotEmpty`、`Pattern`(见 [校验对齐](1.4.0-validation-alignment.md) 的 D7);`pattern` 可写内置名(`PATTERN_35`),Java、Go 各自解析成自己的正则。
- 同一份 YAML 用于 Java、Go;JSON 表示就是同样的结构(数据库、Redis 里存 JSON)。

### 2.1 规则里记录来源与示例

两个可选字段加到**字段规则**(`request` / `response` 下的每个字段项):

| 字段 | 说明 |
|---|---|
| `template` | 套用时记下的模板名,只用于展示和“与模板不一致”的提示,**运行时不读** |
| `example` | 字段示例。Go 的 `FieldRule` 已有 `example`;Java 的 `ParamDataValidate` 要补上,文档生成时用它填 `CsapDocParameter.example` |

旧版本读到这两个字段会忽略(Jackson、Go、YAML 都忽略未知字段);旧版 Java DevTools 重写规则时会丢掉它们。

## 3. 存放位置

两层:

| 层 | 内容 | 位置 | 可写 |
|---|---|---|---|
| **内置模板** | 随 jar 发布的一批常用字段(手机号、邮箱、身份证、URL、分页页码 / 条数、日期、金额等),由现有内置正则组合出来 | jar 内 `META-INF/csap-apidoc/field-templates.yaml`;Go 内嵌同一份 | 否 |
| **项目模板** | 团队自己的模板 | 见下 | 是(受规则存储的可写性限制) |

项目模板的位置**跟着规则存储走**,这样多实例同步、修改记录、回滚、权限、备份都不用另外做:

| 存储 | 项目模板放在 |
|---|---|
| 数据库 | `{prefix}rule` 表里一行**保留键** `@templates`,`rules` 列存 `{"version":1,"templates":[…]}` |
| Redis | `rules` Hash 里保留字段 `@templates`,值同上 |
| YAML / JSON 文件 | `{path}/field-template/api-field-template.yaml`(与 `method-field` 并列) |
| SQLite | 同 YAML 文件(SQLite 库里没有合适的表,不为模板加表);打包运行时不可写,提示同保存规则 |
| ANNOTATION | 不支持项目模板,只有内置模板 |

保留键约定:**以 `@` 开头的规则键不是接口规则**(Java 类名、Go 分组名都不会以 `@` 开头)。所有读取方(Java 的 `RuleStoreParamGroupStrategy`、迁移工具、Go 的各规则来源)加载规则时跳过 `@` 开头的键,不告警;保存 `@templates` 照常走版本号、修改记录、订阅 / 轮询。旧版本读到它会按“规则键格式不对”忽略并打一条警告,不影响使用。

合并:内置模板 + 项目模板,`name` 相同时**项目模板覆盖内置**(团队可以改写“手机号”的提示)。

## 4. 套用与更新

**套用 = 复制,不联动**:

1. DevTools 字段编辑里选“从模板套用”,选一个模板,先显示**预览**(会改哪些项:说明、示例、必填、校验规则)。
2. 确认后,模板里**写了的项**覆盖字段的对应项:`description`、`example`、`required` 各自覆盖;`validate` **整体替换**(不是追加,避免重复套用叠加);模板没写的项不动。
3. 字段规则记下 `template: <模板名>`。之后字段可以随意再改,不影响模板,模板也不影响它。

**模板更新后**:已套用的字段**不自动变化**。DevTools 在字段上比较“字段当前内容”和“模板当前内容”,不一致时显示“与模板 phone-cn 不一致”的提示和“重新套用”按钮(走同样的预览与确认);字段上的 `template` 指向的模板已删除时提示“模板已不存在”。不记录模板版本号,比较的是内容。

**另存为模板**:字段编辑里“存为模板”,把该字段当前的说明、示例、必填、校验规则存成项目模板(填 `name`、`title`),并把字段的 `template` 指向它。

## 5. DevTools 与接口

- 字段校验规则弹窗(现有 `ValidateTableModal`)增加“模板”页:搜索、按分类、显示内置 / 项目标记、套用、存为模板。
- 模板管理抽屉:新增、编辑、删除项目模板(内置的只读,可“复制为项目模板”后改)。
- 接口:`GET /csap/yaml/fieldTemplates`(内置 + 项目合并,标出来源)、`POST /csap/yaml/fieldTemplates`(保存项目模板)、`DELETE /csap/yaml/fieldTemplates/{name}`;不可写时返回 `1007`。
- 套用本身是前端把模板内容写进字段,走现有的保存字段规则接口,不需要新的“套用”接口。

## 6. 实现范围(确认后做)

Java:`FieldTemplate` 模型与 YAML 读写;内置模板文件(先放 15 条左右常用的);按存储读写项目模板(`@templates` 保留键、YAML 文件);`ParamDataValidate` 加 `example`、`template`(并用 `example` 填文档);所有规则读取方跳过 `@` 键;DevTools 接口与页面;测试覆盖格式解析、合并覆盖、各存储读写、保留键不被当成接口规则、套用语义(覆盖、整体替换)。Go 侧:读取同一份 YAML / JSON,`FieldRule` 加 `template`,规则加载跳过 `@` 键,由 go-db 接入。

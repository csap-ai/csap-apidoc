# API 版本管理与破坏性变更检测(csap-apidoc-diff)

状态:已实现(Go v0.2.0,`csap-apidoc-go/cmd/csap-apidoc-diff`)。语言无关:Java 和 Go 服务的 `/csap/apidoc` 输出同一协议,两种语言的文档都能比;工具本身是单个静态二进制,放进 CI 即可。

## 1. 工作方式

```
csap-apidoc-diff snapshot -o baseline.json http://localhost:8080/csap/apidoc   # 存基线(提交进 Git)
csap-apidoc-diff baseline.json http://localhost:8080/csap/apidoc               # 对比,有破坏性变更退出码 1
```

- 输入(旧、新各一份)可以是:`/csap/apidoc` 的 URL(路径为空时补 `/csap/apidoc`)、保存下来的 JSON 文件、`snapshot` 生成的快照文件。
- **快照**是精简后的文档:去掉了每次导出都会变的随机 key、时间戳,字段按路径展开,键有序,内容稳定,适合提交进仓库做基线。
- 输出:`-format text|json|markdown`,`-o 文件`;退出码 0 通过、1 有破坏性变更(或按 `-fail-on` 判定失败)、2 参数或读取错误。
- `-fail-on breaking|warning|never`(默认 breaking);`-min-level info|warning|breaking` 控制报告里列出的最低级别(汇总数字不受影响)。
- 请求 URL 时可用 `-H "Name: Value"` 附带请求头(如 Authorization);报告里只显示不带查询串的地址,不会泄露令牌。

## 2. 比较单位

- **接口标识**:文档里 method 的 `key`(Java 为 `类全名.方法名`,Go 为 `分组.接口名`);没有 key 时用 `方法 + 路径`。同一份文档里标识重复时加 `#2` 后缀。
- **改名**:只在一边出现的标识,如果另一边有"HTTP 方法集合和完整路径集合都相同"的接口,配成改名(`endpoint.renamed`,兼容),并继续比较它们的字段;否则分别报删除和新增。
- **隐藏的接口**(接口、所在 controller 或 `hiddenMethod` 里隐藏)按"不存在"处理,所以新隐藏等同于下线。
- **完整路径** = `apiPath` × `paths` 的组合(规范化斜杠)。
- **字段路径**:请求字段为 `参数名.字段.子字段`(与规则键的写法一致),返回字段为 `字段.子字段`;`children` 与嵌套 `parameters` 都展开,隐藏字段不计。

## 3. 规则表

级别:**breaking** 破坏性(退出码 1)、**warning** 需要留意(`-fail-on warning` 时也失败)、**info** 兼容的变化。

### 接口

| 变更类型(kind) | 级别 | 条件 |
|---|---|---|
| `endpoint.removed` | breaking | 接口标识消失(且不是改名),或被隐藏 |
| `endpoint.added` | info | 新增接口 |
| `endpoint.renamed` | info | 标识变了,方法和路径不变 |
| `endpoint.method.removed` | breaking | 不再支持某个 HTTP 方法 |
| `endpoint.method.added` | info | 新增 HTTP 方法 |
| `endpoint.path.removed` | breaking | 旧路径不再可用(路径变化) |
| `endpoint.path.added` | info | 新增路径 |
| `endpoint.paramtype.changed` | breaking | 接口的参数位置(`paramType`)变化 |
| `endpoint.deprecated` | warning | 状态变为 DEPRECATED |
| `endpoint.description.changed` | info | 接口说明变化 |
| `header.required.added` | breaking | 新增必填请求头,或请求头由可选变必填 |
| `header.added` / `header.required.removed` / `header.removed` | info | 新增可选请求头 / 必填变可选 / 不再声明 |

### 字段

| 变更类型(kind) | 请求字段 | 返回字段 | 条件 |
|---|---|---|---|
| `field.removed` | warning | **breaking** | 字段被删除 |
| `field.added` | info | info | 新增字段(请求字段必填时见 `field.required.added`) |
| `field.type.changed` | breaking | breaking | `dataType` 变化,或 `modelType`(对象/数组/基本类型)变化 |
| `field.required.added` | breaking | — | 请求字段可选变必填,或新增必填请求字段 |
| `field.required.removed` | info | warning | 请求:必填变可选;返回:不再保证一定存在 |
| `field.paramtype.changed` | breaking | — | 请求字段的参数位置(QUERY/BODY/PATH…)变化 |
| `field.validate.changed` | warning | — | 新增或修改了校验规则(变严) |
| `field.validate.relaxed` | info | — | 只删除了校验规则(放宽) |
| `field.length.decreased` | warning | — | 长度上限变小 |
| `field.description.changed` | info | info | 字段说明变化 |

### 枚举

枚举来自 `docEnumList`(及 `enumList`),按枚举名比较取值(code,无 code 用 name)。

| 变更类型(kind) | 级别 | 条件 |
|---|---|---|
| `enum.value.removed` | breaking | 取值减少 |
| `enum.removed` | breaking | 整个枚举被删除 |
| `enum.value.added` / `enum.added` | info | 新增取值 / 新增枚举 |

> 取值**增加**对"客户端遇到不认识的值"可能是破坏性的,但无法从文档判断,默认按兼容处理;需要更严的策略,用 `-fail-on warning` 并配合下面的忽略清单自行取舍,或在评审里关注 `enum.value.added`。

## 4. 忽略清单

`-ignore 文件`(可重复)。每行一条:`接口 [变更类型 [字段]]`,空白分隔,`*` 匹配任意字符(含 `.` 和 `/`),缺省的段等于 `*`,`#` 开头或行内 `#` 之后是注释。三段都命中才忽略。被忽略的变更不计入汇总和退出码,JSON 报告里仍列出并带 `"ignored": true`。

```
# 这个接口整体不检查(内部接口)
com.example.OrderController.legacy
# 所有接口的 data.legacyId 返回字段删除都放行
*  field.removed  data.legacyId
# 已确认下线的接口
example.UserController.list  endpoint.removed
```

枚举这类没有接口的变更,接口段只有 `*` 能命中。

## 5. GitHub Actions 示例

```yaml
name: api-compat
on: pull_request
jobs:
  api-diff:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: { go-version: stable }
      - run: CGO_ENABLED=0 go install github.com/csap-ai/csap-apidoc/csap-apidoc-go/cmd/csap-apidoc-diff@latest

      # 启动被检查的服务(示例:Go 服务;Java 服务用 mvn spring-boot:run 等),等它就绪
      - run: |
          go run ./cmd/server &
          for i in $(seq 1 30); do curl -sf localhost:8080/csap/apidoc >/dev/null && break; sleep 1; done

      # 与仓库里提交的基线对比;有破坏性变更时这一步失败,Markdown 报告写进作业摘要
      - run: |
          csap-apidoc-diff -format markdown -ignore .apidoc-ignore \
            api-baseline.json http://localhost:8080/csap/apidoc | tee -a "$GITHUB_STEP_SUMMARY"
          exit "${PIPESTATUS[0]}"
```

确认变更合理后更新基线并提交:`csap-apidoc-diff snapshot -o api-baseline.json http://localhost:8080/csap/apidoc`。

## 6. 局限

- 只看文档里有的信息:字段的语义变化(含义变了但类型没变)、校验规则的细节行为看不出来。
- 校验规则按"规则文本集合"比较,正则从宽改窄、从窄改宽都只会报 `warning`(变严或被修改),不做语义推断。
- Java 与 Go 同名接口的类型串写法不同(如 `Integer` 与 `int`),所以不要拿 Java 文档和 Go 文档互相比较,只比较同一个服务的两个版本。

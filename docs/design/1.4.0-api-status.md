# 接口上下线状态(开发中 / 完成 / 过时)

状态:约定草案,待审。基于现有 `ApiStatus`:`DEFAULT`(开发阶段)、`FINISH`(完成)、`DEPRECATED`(过时)。本文定:状态怎么存(Java / Go 共用)、各处怎么用。

## 1. 现状

- `@Api(status = …)`、`@ApiOperation(status = …)` 可以标注,默认 `DEFAULT`;文档模型 `CsapDocModelController.status`、`CsapDocMethod.status` 已有值。
- 但**没有任何地方用它**:文档页不显示,OpenAPI 导出不输出 `deprecated`,MCP 不看,DevTools 不能改。
- 规则存储(YAML / SQLite / 数据库 / Redis)里没有状态;Go 没有状态概念。

## 2. 有效状态

一个接口的**有效状态**按下面顺序取第一个有值的:

1. 规则存储里该接口的 `status`(DevTools 改出来的,见第 3 节);
2. 方法上 `@ApiOperation.status`,不是 `DEFAULT` 时;
3. 类上 `@Api.status`,不是 `DEFAULT` 时(整个 Controller 过时,其下接口都过时);
4. `DEFAULT`。

注解的默认值就是 `DEFAULT`,无法区分“没标”和“明确标成开发中”,所以注解里的 `DEFAULT` 视为“没标”;要明确标成开发中只能经规则存储(`"status": "DEFAULT"`)。有效状态写入文档模型 `CsapDocMethod.status`,文档页、OpenAPI、MCP 都读它。

显示名:`DEFAULT` 开发中、`FINISH` 完成、`DEPRECATED` 过时(英文 In development / Stable / Deprecated)。

## 3. 存储格式(Java 与 Go 共用)

状态存在**接口的规则 JSON 里**,与 `request`、`response` 并列,多两个可选字段:

```json
{
  "request": { "...": {} },
  "response": { "...": {} },
  "status": "DEPRECATED",
  "statusNote": "请改用 /v2/users"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | 字符串,可选 | `DEFAULT` / `FINISH` / `DEPRECATED`(与 Java `ApiStatus` 的名字一致,大小写敏感);不存在表示“没有覆盖,按第 2 节往下取”;未知值按不存在处理(向前兼容) |
| `statusNote` | 字符串,可选 | 备注,如替代接口、下线时间;文档页、OpenAPI 描述、MCP 工具说明里显示 |

### 3.1 各存储怎么落

| 存储 | 位置 | 变更 |
|---|---|---|
| YAML / JSON 文件 | `method-field` 文件里该接口下的 `status`、`statusNote` | 无结构变化 |
| 数据库 | `{prefix}rule.rules` 列的 JSON | **表结构不变** |
| Redis | `rules` Hash 里该接口的 JSON | 不变 |
| SQLite | `api_method` 表**已有的 `status` 列**(旧模板遗留,默认 `'DEFAULT'`);备注存到新列 `status_note` | 启动时按现有的列迁移机制补列;因为 `DEFAULT` 是列默认值,读取时 `DEFAULT` 视为“没有覆盖” |

### 3.2 “空规则”的判定要改

数据库、Redis 模式现在“规则为空(request、response 都没有字段)时删除该行”。有了状态后改为:**request、response 都没有字段,并且没有 `status`、`statusNote`** 才算空。只改状态、没有字段规则的接口,是一条只有状态的规则。

### 3.3 兼容性

- 旧版本读取:Java(Jackson)、Go(`encoding/json`、YAML)都忽略未知字段,滚动升级时旧实例不会报错,只是看不到状态。
- 旧版本写入:旧版 Java DevTools 保存某接口的字段规则时会按它认识的结构整行重写,**会丢掉该接口的 `status`**。数据库 / Redis 模式多实例混跑旧版本时要注意,升级时一次升完。
- 同步:状态随规则一起走版本号、修改记录、回滚、订阅 / 轮询,不需要另外的机制;迁移工具(YAML / SQLite ↔ 数据库 / Redis)照常搬运。

### 3.4 Go 侧需要做的

`strategy.MethodRules` 加 `Status string \`json:"status,omitempty" yaml:"status,omitempty"\`` 和 `StatusNote`;规则保存、导入、各存储读写按上面的“空规则”判定;文档模型里带出状态(若 Go 的文档页 / OpenAPI 也要用)。具体由 go-db 接入。

## 4. 各处用法

### 4.1 文档页

- 接口行和详情标题显示状态标记:`FINISH` 显示“完成”,`DEPRECATED` 显示“过时”(划线 + 备注);`DEFAULT` **不显示标记**(绝大多数接口没标注,全部显示“开发中”只是噪音)。
- 筛选:状态下拉“全部 / 开发中 / 完成 / 过时”,按有效状态过滤;URL 带参数,方便分享。
- 过时的备注(`statusNote`)显示在接口说明里。

### 4.2 OpenAPI / Postman 导出

- 有效状态 `DEPRECATED` → operation 输出 `deprecated: true`。
- 非 `DEFAULT` 的状态额外输出 `x-csap-status: FINISH | DEPRECATED`;有备注时追加到 `description` 末尾。
- Postman:过时接口名称前加 `[过时] `。

### 4.3 MCP

- **过时接口默认不暴露**(要用必须在 DevTools MCP 页里逐个打开,与写操作类似);新增 `csap.apidoc.mcp.expose-deprecated`(默认 `false`),设为 `true` 则按普通接口的默认规则处理。
- **开发中不隐藏**:绝大多数接口没有标注状态,有效状态都是 `DEFAULT`,按它隐藏等于全隐藏。想把没完成的接口挡住,请在 MCP 页里关掉,或把重要的稳定接口标成 `FINISH`。
- 工具说明前缀状态:`[过时] ` / `[完成] `(`DEFAULT` 不加);有备注时追加“(备注)”。AI 因此知道该不该用。
- MCP 页的工具列表增加“状态”列,并按状态筛选。

### 4.4 DevTools

- 接口列表显示状态,可下拉修改并填备注,保存走规则存储的正常保存(有修改记录、可回滚、其他实例同步)。
- 新增接口 `POST /csap/yaml/setStatus`,请求体 `{className, methodName, status, statusNote}`;`status` 传 `null` 表示清除覆盖,回到注解 / 默认。
- 只读模式、打包运行不可写的情况,返回与保存字段规则时相同的 `1007` 提示。
- ANNOTATION 模式没有规则存储,不能改状态,提示改注解或换存储。

## 5. 实现(已完成)

文档页菜单树的方法节点带 `status`、`statusNote`(`/csap/apidoc/parent`);MCP 工具说明前缀状态,`expose-deprecated` 默认 `false`;DevTools 的 `setStatus` 经正常保存写入规则存储。下面是原先列的范围。

Java:`ParamGroupMethodProperty` 加 `status`、`statusNote`;“空规则”判定改在 `RuleJson.isEmpty`、`RuleMigrator`;文档生成计算有效状态;OpenAPI / Postman 输出;MCP 暴露与说明;DevTools 接口与页面;文档页(`csap-apidoc-ui`)显示与筛选;SQLite 的 `status`、`status_note` 列。测试覆盖有效状态的优先级、各存储的保存与读回、旧结构的 JSON 读取、OpenAPI、MCP 默认暴露。

## 6. 待定

- Go 文档页是否同步显示:由 go-db 决定。

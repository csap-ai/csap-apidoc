# 1.3.0 设计:文档即 MCP

> 2026-11-17 起草。范围以 [ROADMAP](../ROADMAP.md) 的 1.3.0 为准;目标发布 2026-12-11。

## 1. 目标与范围

服务自身提供 `/csap/mcp`(MCP Streamable HTTP),把文档里的接口变成 MCP 工具,AI 智能体可以直接查询、调用。

| 本轮做 | 本轮不做(列为后续) |
|---|---|
| Java 内嵌 MCP 端点(Spring Boot 2 / 3 一个 jar) | 独立聚合服务 `csap-apidoc-mcp` 进程(多服务、stdio) |
| 工具生成、调用转发、返回过滤、鉴权、审计 | Go 版 MCP |
| 规则文件(YAML / SQLite)保存暴露范围、改写、鉴权方式 | MCP resources / prompts、SSE 推送、`subscriptions/listen` |
| DevTools "MCP" 页面、Agent Skill、官网文档 | OAuth 2.1 授权服务器对接(MCP Authorization 规范) |

**默认关闭**,`csap.apidoc.mcp.enabled=true` 开启;未开启时端点不注册(404)。

## 2. 模块划分

新建模块 `ai.csap.apidoc:csap-apidoc-mcp`,由 `csap-apidoc-boot-starter` 引入。和 1.2.0 的 `csap-apidoc-runtime` 一样:

- 只用 spring-web / spring-webmvc 的抽象(`@RestController`、`RequestMappingHandlerMapping`、`HandlerMethod`),**不引用 javax / jakarta Servlet 类**,按 Spring 5.2 编译、Java 11 字节码,一个 jar 同时用于 Boot 2 和 3。
- 取客户端 IP 等只能从 Servlet 请求拿到的信息,通过 `RequestContextHolder` + 反射调用 `getRemoteAddr()`,不产生编译期依赖。
- 自动配置同时登记 `spring.factories`(Boot 2)和 `AutoConfiguration.imports`(Boot 3)。

不用官方 MCP Java SDK:`io.modelcontextprotocol.sdk:mcp-core` 2.2.0 是 Java 17 字节码(class major 61),并依赖 reactor-core、jakarta.servlet,不满足本项目 Java 11 / Boot 2 的要求。协议本身很小(JSON-RPC 2.0 + 几个方法),自己实现最小协议,只依赖 Jackson(Spring Boot web 应用必然存在)。

```
ai.csap.apidoc.mcp
├── autoconfigure   McpProperties、McpAutoConfiguration、McpDevtoolsAutoConfiguration
├── protocol        JSON-RPC 编解码、版本协商、方法分派(McpServer,纯 Java,可单测)
├── tool            ToolCatalog(文档 + HandlerMapping → 工具)、SchemaBuilder、ParamBinding
├── invoke          LoopbackInvoker(本机回环 HTTP 调用)
├── config          McpSettings(规则文件模型)、YAML / SQLite / 内存三种存储
├── audit           AuditLog(环形缓冲)+ SqliteAuditSink、Redactor(脱敏、截断)
├── security        McpAuthenticator(令牌 / 透传)、Origin 校验
└── web             McpEndpointController(/csap/mcp)、McpAdminController(DevTools 接口)
```

## 3. 协议

### 3.1 版本

MCP 当前版本(2026-11 确认)是 **2026-07-28**,它去掉了 `initialize` 握手(无状态,每个请求在 `_meta` 里带版本),并要求服务端实现 `server/discover`。主流客户端(Claude Code、Cursor 等)目前仍以握手式版本为主。因此实现为规范所说的 **dual-era 服务端**:

| 时代 | 版本 | 识别方式 |
|---|---|---|
| modern | `2026-07-28` | 请求 `params._meta["io.modelcontextprotocol/protocolVersion"]` 或 `MCP-Protocol-Version` 头为 modern 版本 |
| legacy | `2025-11-25`、`2025-06-18`、`2025-03-26` | 其余情况;`initialize` 协商 |

- **legacy**:`initialize` 时客户端请求的版本在支持列表里就原样返回,否则返回 `2025-11-25`。后续请求的 `MCP-Protocol-Version` 头若存在必须是支持的版本(否则 400);缺省按 `2025-03-26` 处理(规范允许)。不发 `Mcp-Session-Id`(会话是可选的,本实现无状态)。支持 `initialize`、`notifications/initialized`、`ping`、`tools/list`、`tools/call`;2025-03-26 的批量请求也支持。
- **modern**:校验 `MCP-Protocol-Version`、`Mcp-Method`、`Mcp-Name`(`tools/call`)头与请求体一致(`Mcp-Name` 支持 `=?base64?…?=`),不一致或缺失返回 400 + `-32020 HeaderMismatch`;版本不支持返回 400 + `-32022`,`data.supported` 列出全部支持版本;未知方法 404 + `-32601`。结果带 `resultType: "complete"`、`_meta["io.modelcontextprotocol/serverInfo"]`;`tools/list`、`server/discover` 带 `ttlMs`、`cacheScope: "private"`。
- 两个时代都响应 `server/discover`。
- 只返回 `application/json`,不开 SSE 流(规范允许服务端对每个请求自选 JSON 或 SSE)。`GET` / `DELETE` 返回 405。通知(无 `id`)返回 202。
- `Origin` 头存在且不在 `allowed-origins` 里时返回 403(防 DNS rebinding,规范 MUST)。

### 3.2 工具

每个文档接口(未隐藏)一个工具:

| 字段 | 来源 |
|---|---|
| `name` | 默认 `{类简名去掉 Controller}_{方法名}`(如 `Product_getProduct`),只保留 `[A-Za-z0-9_-]`,最长 64(兼容 Claude 等对工具名更严格的客户端);重名加 `_2`… ;可在 DevTools 改写 |
| `title` | 文档标题(`@ApiOperation` value) |
| `description` | 标题 + 描述 + `HTTP GET /path`;可改写 |
| `inputSchema` | 见 3.3 |
| `annotations` | GET → `readOnlyHint`;DELETE → `destructiveHint`;GET/PUT/DELETE → `idempotentHint`;`openWorldHint: false` |

工具列表按工具名排序,保证顺序稳定(规范 SHOULD)。

### 3.3 参数与 inputSchema

只看文档无法可靠知道参数位置(例如文档里路径变量常被记成 `DEFAULT`/`BODY`)。所以**以 Spring 的 `RequestMappingHandlerMapping` 为准确定 URL、HTTP 方法和参数位置,以文档为准提供说明、必填、类型和对象字段**:

| 方法参数 | 位置 | schema 属性 |
|---|---|---|
| `@PathVariable` | path | 顶层,必填 |
| `@RequestParam` / 无注解的简单类型 | query | 顶层 |
| `@RequestHeader` | header | 顶层 |
| `@RequestBody` | body | `body`(对象 / 数组 / 简单类型,按文档字段生成) |
| 无注解的对象(`@ModelAttribute`) | query | 对象字段逐个展开到顶层(嵌套用 `a.b`) |
| Servlet / Spring 内部类型(`Principal`、`BindingResult`、`HttpServletRequest` 等) | — | 忽略 |
| `MultipartFile` 等 | — | 工具标为不支持,不暴露 |

顶层重名时后者加后缀(`_query`、`_header`)。类型映射:整数类 → `integer`,`BigDecimal`/浮点 → `number`,`Boolean` → `boolean`,集合 / 数组 → `array`(`items` 按泛型),`Map` → `object`,对象 → `object` + `properties`(按文档子字段,深度上限 8,防循环),其余 → `string`。文档的校验规则(`pattern`、message)写进属性的 `description`。

## 4. 调用转发:本机回环 HTTP

`tools/call` 按工具绑定拼出 URL(路径变量用 `UriUtils.encodePathSegment` 编码,防止 `../` 之类越界)、查询串、请求头和请求体,用 JDK 11 自带 `java.net.http.HttpClient` 请求 `http://127.0.0.1:{本服务端口}{context-path}{servlet-path}{接口路径}`。

**为什么不用 DispatcherServlet 内部分派:**

| | 回环 HTTP(采用) | DispatcherServlet 内部分派 |
|---|---|---|
| Boot 2 / 3 一个 jar | 只用 JDK HttpClient,无 Servlet 依赖 | 要构造 `HttpServletRequest/Response`,javax 与 jakarta 两套,只能反射或拆两个 jar |
| Servlet Filter(Spring Security、租户、链路追踪、限流) | 完整经过,和真实调用一致 | 绕过,透传鉴权失效,还可能绕过安全控制 |
| 返回字段过滤(1.2.0) | 目标接口的 `ResponseBodyAdvice` 自然生效 | 同样生效,但还需处理异步、错误页 |
| 代价 | 多一次本机 TCP 往返(亚毫秒);占用一个容器线程 | 无网络开销 |

端口来自 `WebServerInitializedEvent`;HTTPS、反向代理或端口不可直连时用 `csap.apidoc.mcp.base-url` 指定。超时 `call-timeout`(默认 30s)。

**返回**:响应体按文本放进 `content[0].text`,超过 `max-result-chars`(默认 50000)截断并注明;2xx 以外 `isError: true`,文本以 `HTTP {状态码}` 开头,方便模型自我纠正。**返回字段过滤**:`csap.apidoc.runtime.filter.enabled=true` 时目标接口本身就按 1.2.0 规则输出,MCP 拿到的就是过滤后的结果,不需要另写一套。

## 5. 鉴权与安全模型

| 模式 | `/csap/mcp` 本身 | 转发给目标接口的头 |
|---|---|---|
| `token`(默认) | 需 `Authorization: Bearer <token>`,令牌在 `csap.apidoc.mcp.auth.tokens` 配置(名称 + 值,建议用环境变量占位);未配置任何令牌时一律 401(fail-closed),启动时告警 | `forward-headers` 里除 `Authorization` 之外的头 + `upstream-headers`(服务自身调用凭据) |
| `passthrough` | 不校验 | `forward-headers`(默认 `Authorization`、`Cookie`)原样转发,由目标接口自己的鉴权(如 Spring Security)把关 + `upstream-headers` |

- 令牌比较用 SHA-256 后 `MessageDigest.isEqual`,避免时序侧信道;日志、审计只记令牌**名称**。
- 鉴权方式(`mode`、`forwardHeaders`)可在 DevTools 改并保存到规则文件,覆盖配置文件的默认值;**令牌值只在配置文件 / 环境变量里**,不进规则文件、不经 DevTools 接口返回。
- 默认只暴露 GET;写操作必须在 DevTools 逐个勾选(或在规则文件里 `enabled: true`)。
- 只会调用本服务里文档登记的接口,URL 由服务端拼接,参数值不能改变目标主机或路径层级(无 SSRF)。
- 不转发逐跳头(`Connection`、`Host`、`Content-Length` 等);回环请求带 `X-Csap-Mcp-Tool` 头便于目标服务日志区分。
- Spring Security 应用需要放行 `/csap/mcp` 并对它关闭 CSRF(文档给出示例)。

## 6. 配置与持久化

### 6.1 配置项(`McpProperties`)

```yaml
csap:
  apidoc:
    mcp:
      enabled: false              # 总开关
      path: /csap/mcp
      base-url:                   # 回环地址,默认 http://127.0.0.1:{端口}{context-path}
      call-timeout: 30s
      max-result-chars: 50000
      expose-get-by-default: true # 未单独设置的 GET 接口默认暴露
      allowed-origins: []         # 浏览器来源白名单;Origin 不在其中则 403
      instructions:               # 发给 AI 的服务说明,默认用文档标题和描述
      store: auto                 # auto | yaml | sqlite | memory
      config-file:                # 规则文件显式路径(生产环境可写位置)
      auth:
        mode: token               # token | passthrough(规则文件里的设置优先)
        tokens:
          - name: claude-code
            value: ${CSAP_MCP_TOKEN:}
        forward-headers: [Authorization, Cookie]
        upstream-headers: {}      # 每次回环调用附加的头,如服务账号凭据
      audit:
        enabled: true
        capacity: 500             # 内存环形缓冲条数
        persist: false            # true 时落 SQLite
        sqlite-file: csap-mcp-audit.db
        max-rows: 10000
        max-summary-chars: 512
        mask-fields: []           # 追加的脱敏字段名
```

### 6.2 规则文件

沿用字段规则的存储策略(`@EnableApidoc(paramType=…)`):`SQL_LITE` 存进同一个 SQLite 库,其余(YAML / JSON / 注解)存 `{path}/mcp.yaml`。`store` 可强制指定。位置解析与字段规则一致:开发时(classpath 根是目录)写到 `src/main/resources/{path}/`,打成 jar 后 classpath 只读,DevTools 修改只在内存生效并提示,需要持久化时配 `config-file`。

YAML:

```yaml
auth:
  mode: token
  forwardHeaders: [Authorization, Cookie]
tools:
  com.example.UserController.get:     # 文档方法 key
    enabled: true
    name: get_user
    description: 按 ID 查询用户
  com.example.UserController.delete:
    enabled: false
```

SQLite:表 `mcp_setting(name PK, value)` 存鉴权设置,表 `mcp_tool(method_key PK, enabled, name, description, updated_at)` 存工具设置,按需建表,不影响已有表。

DevTools 修改后立即生效(内存中替换不可变快照),再写入存储。

## 7. 审计

- 每次 `tools/call` 和每次鉴权失败记一条:时间、调用方(令牌名,透传模式为来源 IP)、工具、HTTP 方法与路径、参数摘要、HTTP 状态码 / 错误、结果摘要、耗时。
- **脱敏**:参数和结果按 JSON 递归处理,字段名(忽略大小写、去掉 `-`/`_`)含 `password`、`passwd`、`pwd`、`secret`、`token`、`authorization`、`apikey`、`credential`、`cookie`、`session`、`privatekey`、`accesskey` 及 `mask-fields` 的值替换为 `***`;再截断到 `max-summary-chars`。请求头从不记录。
- 内存环形缓冲(`capacity`);`persist: true` 时由单线程异步写 SQLite,超过 `max-rows` 删除最旧记录。
- DevTools 接口:`GET /devtools/mcp/audit?limit=&tool=&caller=`。

## 10. 风险

| 风险 | 应对 |
|---|---|
| 回环调用占用容器线程,极端情况下线程池耗尽 | 默认 30s 超时;文档说明;容器线程默认 200,MCP 调用量远低于此 |
| HTTPS / 只监听特定网卡 / 有前置网关时 127.0.0.1 不通 | `base-url` 配置 |
| Spring Security 默认拦截 POST(CSRF) | 文档给出放行示例 |
| 文档参数信息不完整(如 YAML 策略下请求体字段未配置) | 以 HandlerMapping 为准保证能调用;对象字段缺失时 `body` 退化为宽松 `object` |
| 写操作被 AI 误调用 | 默认只暴露 GET;`destructiveHint`;审计 |
| 协议还在演进(2026-07-28 刚去掉握手) | dual-era 实现,两边都覆盖;协议层集中在 `protocol` 包 |
| 同名重载方法共用一个 key | 与 1.2.0 规则一致,取 HTTP 方法匹配的第一个,文档写明 |

## 11. 实现记录(2026-11-17)

- 与设计一致;工具名默认去掉类名的 `Controller` 后缀。
- 状态码一律用 `int` 构造 `ResponseEntity`:`ResponseEntity.status(HttpStatus)` 在 Spring 6 变成 `HttpStatusCode` 参数,按 Spring 5.2 编译会在 Boot 3 上 `NoSuchMethodError`;`ServletRequestAttributes.getRequest()` 同理只能反射调用。
- 端点直接返回 `byte[]`,不经过应用的 JSON 消息转换器;若应用有对所有返回值生效的全局 `ResponseBodyAdvice` 包装,需要排除 `/csap/mcp`(文档说明)。
- 测试:模块单测 21 个;Boot 2.7 / Boot 3.2 示例各 6 个端到端;Boot 2.3 只做了编译期保证(按 Spring 5.2 编译),未在 2.3 上跑端到端。
- 冒烟:标准库 Python 客户端对示例服务走完 legacy(2025-06-18)与 modern(2026-07-28)两种流程。

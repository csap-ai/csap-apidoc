## 1. 范围

**做**:

1. Mock:服务内嵌,默认关闭;按文档里的返回结构生成数据;数据可复现;可在规则里指定字段的 Mock 值;文档页"在线调试"可一键切到 Mock。
2. JSON Schema 导出:每个接口的请求、返回模型 → JSON Schema 2020-12,带字段说明、必填、校验规则映射。
3. JSON Schema 导入:把(导出再被人修改的,或外部提供的)Schema 里的说明、必填、示例、校验转成**字段规则**。

**不做**:快照覆盖 Mock、有状态 Mock、故障注入、延迟抖动、从 JSON Schema 直接生成"文档里不存在的接口/字段"(见 5.3)、OpenAPI 导入。

## 2. Mock:形态与约定

### 2.1 入口:路径前缀(不用请求头切换)

Mock 地址 = `/csap/mock` + 原接口路径。`POST /api/users/{id}` 的 Mock 是 `POST /csap/mock/api/users/42`。

**选前缀、不选请求头的理由**:

- 请求头切换要在真实路由前面拦截请求(Java 是 Filter,Go 要给每个适配器各写中间件),一旦在生产误开,真实接口会被悄悄替换成假数据;前缀方式永远不碰真实路由,关闭时 `/csap/mock/**` 直接 404。
- 前缀落在已经保留给框架的 `/csap` 命名空间下,不会和业务路由冲突;curl、浏览器、前端调试都能直接用。
- 不依赖框架拦截器:Go 的 net/http、gin 两种适配器只需要多挂一条路由。

固定为 `/csap/mock`,**不提供 base-path 配置**(两种语言路径必须一致,UI 也要靠它识别)。

### 2.2 请求如何匹配接口

1. 去掉前缀,得到原路径。接口完整路径 = `apiPath[0]` + `paths[0]`,各段首尾 `/` 规整为单个 `/`(与现有 OpenAPI 导出一致)。
2. 路径按 `/` 分段;`{name}` 和 `{name:正则}` 各匹配**一个**非空段(不实现 `*`、`**`)。
3. HTTP 方法必须在接口的 `methods` 里(`methods` 为空视为任意方法)。
4. 多个接口都匹配时,排序取第一个:字面段数多的优先 → 占位符少的优先 → `key` 字典序小的优先。
5. 路径匹配但方法都不对:`405` + `Allow` 头;路径不存在:`404`。两者的 body 都是
   `{"code":"MOCK_NOT_FOUND","message":"no documented endpoint for GET /x"}`(405 的 code 为 `MOCK_METHOD_NOT_ALLOWED`)。
6. `hidden=true` 的接口、不在文档里的接口一律 404(Mock 只反映"文档里有的")。状态为 `DEPRECATED` 的照常 Mock。

Mock **不**校验请求(路径参数、查询、请求体、请求头都不看),不调用业务代码。宿主应用自己的过滤器、拦截器、网关对 `/csap/mock/**` 照常生效(这是 Spring / net/http 的行为,不特殊处理)。

### 2.3 响应

- 状态码 `200`,`Content-Type: application/json;charset=UTF-8`。
- 响应头:`X-CSAP-Mock: 1`、`X-CSAP-Mock-Operation: <接口 key>`、`X-CSAP-Mock-Seed: <本次使用的种子>`。
- body = 按 2.5 生成的 JSON。**文档里的返回结构就是实际返回结构**(含统一包装),Mock 不另外加包装。
- 取接口的**第一个**返回模型 `response[0]`:`OBJECT` / `T_OBJECT` → 对象;`ARRAY` → 数组,元素是对象;`BASE_DATA` → 单个标量,类型取模型的 `name`(如 `Long`)。没有返回模型 → `200` + 空 body。(与 Go 现有 OpenAPI 导出一致;Java 现有 OpenAPI 导出会合并多个模型,Mock 不合并。)
- 隐藏字段(`hidden=true`)不输出。规则里 `include: false` 的返回字段本来就不在文档里,所以也不输出。

### 2.4 配置(Java 属性名;Go 用同名语义的 Option,命名由 Go 实现者定)

| 属性 | 默认 | 含义 |
|---|---|---|
| `csap.apidoc.mock.enabled` | `false` | 总开关。关闭时不注册 `/csap/mock/**`,也不注册 `/csap/mock-status` |
| `csap.apidoc.mock.seed` | `csap` | 随机种子(任意字符串);设为 `random` 表示每次请求用时间生成新种子(不可复现) |
| `csap.apidoc.mock.array-size` | `2` | 数组默认长度,范围 0~10,超出按边界处理 |
| `csap.apidoc.mock.max-depth` | `6` | 对象嵌套深度上限,范围 1~20 |
| `csap.apidoc.mock.delay-ms` | `0` | 每次响应前固定等待毫秒数(调试 loading 状态用) |

单次请求可覆盖种子:请求头 `X-CSAP-Mock-Seed` 或查询参数 `_csap_mock_seed`(请求头优先)。

**启用时启动日志必须打一行 WARN**:`csap-apidoc mock is ENABLED, /csap/mock/** returns synthetic data; do not enable in production`。访问控制沿用文档端点(`/csap/apidoc`)的同一套,不单独加。

### 2.5 生成规则(两种语言逐条照做)

#### 2.5.1 可复现的随机数

不使用语言自带的随机数。每个节点用自己的路径派生一个 64 位无符号数 `r`,**与生成顺序无关**:

```
path  : 根为 "$";对象成员 path + "." + 字段名;数组元素 path + "[" + 下标 + "]"
        例:$.data.orders[1].amount     (BASE_DATA 与 ARRAY 返回:根 "$" / 元素 "$[0]")
r     = splitmix64( fnv1a64( UTF-8(seed + "\n" + path) ) )

fnv1a64:  h = 0xcbf29ce484222325;  对每个字节 b: h = (h ^ b) * 0x100000001b3   (mod 2^64)
splitmix64(x): x = x + 0x9e3779b97f4a7c15
               z = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9
               z = (z ^ (z >> 27)) * 0x94d049bb133111eb
               return z ^ (z >> 31)                                    (全部 mod 2^64,>> 为逻辑右移)
```

Java 用 `long` + `>>>` + `Long.remainderUnsigned`;Go 用 `uint64`。下文 `r % n` 都是无符号取模。

#### 2.5.2 类型归一

`dataType` 先归一成 kind:去掉泛型和包名,转小写,按下表(自上而下,命中即止)。Java 的 `String`/`Integer`、Go 的 `string`/`int32` 等写法都在表里。

| dataType(忽略大小写、忽略包名/泛型) | kind |
|---|---|
| 以 `[]` 结尾;或 `list` `set` `collection` `iterable` `array` 及以它们结尾的名字(`ArrayList` 等) | `array`,元素类型 = `<>` 里的类型 / `[]` 前面的类型(缺省 `string`) |
| `int` `integer` `int32` `short` `byte` `long` `int64` `biginteger` `atomicinteger` `atomiclong` | `integer` |
| `double` `float` `float32` `float64` `bigdecimal` `number` | `number` |
| `boolean` `bool` | `boolean` |
| `localdate` | `date` |
| `localdatetime` `date` `offsetdatetime` `zoneddatetime` `instant` `timestamp` `time`(Go 的 `time.Time`) | `datetime` |
| `localtime` | `time` |
| 以 `map` 结尾、`object` `jsonnode` `jsonobject` | `object` |
| 其他一切(含自定义类名) | `string` |

另:`modelType == ARRAY` 的字段按 `array` 处理。`Number` 在 Go 现有 OpenAPI 里被当成 string,新代码**按本表当 `number`**,不要沿用旧行为。

#### 2.5.3 取值优先级(标量字段,自上而下,命中即止)

| # | 来源 | 规则 |
|---|---|---|
| 1 | 规则里的 `mock` | 见 2.6 |
| 2 | `example` | 非空时,按 kind 转换:`integer` 要整数文本,`number` 要有限小数,`boolean` 要 `true`/`false`(忽略大小写);`string/date/datetime/time` 原样。**转换失败就当没有,继续往下** |
| 3 | `defaultValue` | 同上 |
| 4 | 枚举 | 候选来自校验规则 `type=Enum` 的 `pattern`(逗号分隔,去空白,去空项),没有则取字段 `extendDescr` 里每项的 `name`。取 `candidates[r % n]`,按 kind 转换,失败就当没有 |
| 5 | 数值约束(`integer`/`number`) | 见下"数值" |
| 6 | 字段名启发式 | 见 2.5.4 |
| 7 | 类型默认值 | 见下表 |

**类型默认值**(第 7 步;`mock`/`example`/`default`/枚举都没命中):

| kind | 值 |
|---|---|
| `string` | `"string"` |
| `integer` | `1 + r % 100` |
| `number` | 保留两位小数:`round(1 + (r % 9901) / 100, 2)`,即 1.00 ~ 100.00 |
| `boolean` | `r % 2 == 0` |
| `date` | `2026-01-01` 加 `r % 365` 天,`yyyy-MM-dd` |
| `datetime` | 日期同上;时间 = `(r >> 16) % 86400` 秒折算成 `HH:mm:ss`;输出 `yyyy-MM-ddTHH:mm:ssZ` |
| `time` | 同上的 `HH:mm:ss` |
| `object`(无子字段) | `{}` |

**数值**(第 5 步):校验里 `type=Min` / `Max` 的 `pattern` 是边界(各取最严的)。`integer`:`lo = Min 或 1`;`hi = Max 或 (有 Min 时 lo+99,否则 100)`;`hi<lo` 时 `hi=lo`;值 = `lo + r % min(hi-lo+1, 2^53)`。`number`:同样取 `lo/hi`(默认 1.0 / 100.0 或 lo+99),值 = `round(lo + (r % (round((hi-lo)*100)+1)) / 100, 2)`。**没有 Min/Max 时**第 5 步不生效,先走 2.5.4 再走类型默认值。

**字符串长度约束**:对第 6、7 步(启发式、类型默认值)得到的字符串(`mock`、`example`、`defaultValue`、枚举得到的值不裁剪、不补齐),若有 `type=Length` 或 `Size` 的校验,`pattern` 为 `"最小,最大"`(`"n"` 表示恰好 n,`"n,"` 表示无上限):不足最小长度用 `x` 在末尾补齐,超过最大长度从末尾截断(按字符,不是字节)。

**`Pattern`(正则)校验不参与生成**:从正则反推字符串在两种语言里很难一致。需要符合正则的值,用 `example` 或 `mock` 指定。

#### 2.5.4 字段名启发式

字段名 `name` 去掉 `_`、`-` 后转小写得到 `low`。自上而下,命中即止。只在 `mock`/`example`/`default`/枚举都没有时才用。

| 条件 | kind | 值 |
|---|---|---|
| `low` ∈ {`message`,`msg`} | string | `"ok"` |
| `low` == `code` | string | `"200"` |
| `low` == `code` | integer | `200` |
| `low` == `success` | boolean | `true` |
| `low` == `email` | string | `"user" + (r % 1000) + "@example.com"` |
| `low` ∈ {`phone`,`mobile`,`tel`,`telephone`,`cellphone`} | string | `"13" + (r % 10^9 补零到 9 位)` |
| `low` ∈ {`name`,`username`,`nickname`,`realname`,`fullname`} | string | `["Alice","Bob","Carol","David"][r % 4]` |
| 原字段名匹配 `^id$`(忽略大小写)、`[a-z0-9](Id|ID)$`、`_id$` | string | `"id-" + 小写 8 位十六进制(r >> 32)` |
| 同上(id 类) | integer | `1000 + r % 9000` |
| `low` ∈ {`url`,`link`,`website`,`homepage`,`avatar`,`image`,`img`,`icon`,`logo`,`picture`} | string | `"https://example.com/" + 原字段名` |
| `low` ∈ {`page`,`pageno`,`pagenum`,`current`,`pageindex`} | integer | `1` |
| `low` ∈ {`pagesize`,`size`,`limit`,`perpage`} | integer | `10` |
| `low` == `age` | integer | `18 + r % 60` |

integer 的启发式只在没有 Min/Max 约束时生效(有约束走第 5 步)。启发式没有开关:要覆盖就写 `example` 或 `mock`。

#### 2.5.5 数组、对象、深度

- **数组**:长度 `n = array-size`,再按字段上的 `Size`/`Length` 校验收紧:`n = max(n, 最小)`,有上限时 `n = min(n, 最大)`;有 `NotEmpty` 时 `n = max(n, 1)`;最后夹到 0~10。数组字段本身的 `example`/`defaultValue` 不用。
- 有子字段的数组:每个元素是对象,元素 path 为 `path[i]`,元素里再按字段递归。
- 没有子字段的数组:元素类型取 `dataType` 里的元素类型,元素 path 同上,元素**不继承**字段上的 `example`/`validate`,字段名启发式用数组字段自己的名字。
- **对象**(有子字段):递归;对象节点自己没有 `r`,它的成员各用自己的路径。无子字段的 `object` kind 输出 `{}`。
- **深度**:根对象深度为 1,每进入一层子对象(含数组元素对象)深度 +1。进入的深度 > `max-depth` 时:对象字段输出 `null`,有子字段的数组输出 `[]`。文档本身是已展开的有限树,不会无限递归,这个上限只是兜底。
- **字段顺序**:按文档里的字段顺序输出。
- `hidden=true` 或没有 `name` 的字段跳过。

### 2.6 在规则里指定 Mock 值

字段规则(YAML / 数据库 / Redis 里同一份结构)新增可选键 `mock`,与 `example` 并列。值是任意 YAML/JSON 值:

```yaml
demo.UserController:
  detail:
    response:
      data.level:
        mock: "@oneOf(1,2,3)"      # 表达式
      data.token:
        mock: "@uuid"
      data.vip:
        mock: true                 # 字面值:数字、布尔、字符串、数组、对象都原样输出,不做类型转换
      data.extra:
        mock: { a: 1, b: [1, 2] }  # 对有子字段的对象/数组也生效,整体替换
```

- 不是字符串的 `mock`,原样输出。
- 字符串以 `@@` 开头:去掉一个 `@` 后当普通字符串(转义)。
- 字符串以 `@` 开头且是下面之一,按表求值;**其他 `@xxx` 原样输出**:

| 表达式 | 值 |
|---|---|
| `@int(lo,hi)` | `lo + r % (hi-lo+1)`(`hi<lo` 取 `lo`);lo、hi 为整数 |
| `@oneOf(a,b,c)` | 候选按逗号拆分、去空白,取 `candidates[r % n]`,按字段 kind 转换,转换失败就原样字符串 |
| `@uuid` | 令 `h = 16 位小写十六进制(r) + 16 位小写十六进制(splitmix64(r))`,输出 `h[0:8]-h[8:12]-4h[13:16]-8h[17:20]-h[20:32]` |

- `mock` 在文档 JSON 里体现为字段(`Parameter`)上的 `mock` 属性(**新增、可选、加性**:没有时不输出,旧前端忽略)。Java 的 `CsapDocParameter` 与 Go 的 `model.Parameter` 各加一个 `Mock` 字段(任意 JSON 值)。
- 需要改动规则模型:Java 的规则解析/合并(YAML、SQLite、数据库、Redis 共用)和 Go 的 `strategy.FieldRule` 都要透传 `mock`。数据库/Redis 里规则是 JSON 文本,不需要改表结构。
- `mock` 只在 Mock 响应里使用,不影响文档页的展示以外的任何东西(文档页的字段说明里**不**显示它)。

### 2.7 文档页"在线调试"一键切到 Mock

- 新增 `GET /csap/mock-status`:Mock 开启时返回 `{"enabled":true,"prefix":"/csap/mock","seed":"csap"}`(外层沿用文档接口的统一包装),关闭时 404(路由根本没注册)。
- 文档页启动时探测一次。探测成功,"在线调试"的环境选择里多出一个预设环境"Mock",基地址为 `当前 origin + 上下文路径 + /csap/mock`,选中后请求发往 Mock;响应里带 `X-CSAP-Mock` 头时,响应信息行显示一个"Mock"小标记。
- 探测失败(Mock 未开启,或旧版本服务)不显示任何东西。
- 前端是 Java 与 Go 共用的同一份(`csap-apidoc-ui`),所以只需改一次,但两种语言的 `/csap/mock-status` 必须一致。

## 4. JSON Schema 导出

### 4.1 端点(Java、Go 一致)

| 端点 | 作用 |
|---|---|
| `GET /csap/schema.json` | 全部接口的合集(下面 4.2)。`?download=true` 时加 `Content-Disposition: attachment; filename="csap-schema.json"` |
| `GET /csap/schema/method?key=<接口 key>` | 单个接口的 `{operationId,method,path,summary,deprecated,request,response}`,`request`/`response` 各自是带 `$schema` 的独立 Schema(没有时为 `null`);key 不存在 `404`。与 `GET /csap/apidoc/method` 一样用查询参数,因为 key 里有 `.` |

与 `/csap/openapi.json` 一样**始终开启**(只读文档导出),返回的是**裸 JSON**(不套 `ApidocResult` 外层),这样文件可直接保存使用。隐藏接口(`hidden=true`)不导出;`DEPRECATED` 接口导出且 `deprecated:true`。

### 4.2 合集文件格式

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "<apiInfo.title>",
  "x-csap-schema-version": 1,
  "x-csap-operations": [
    { "operationId": "demo.UserController.create", "method": "POST", "path": "/api/users/{tenant}",
      "summary": "创建用户", "deprecated": false,
      "request": "#/$defs/demo.UserController.create.request",
      "response": "#/$defs/demo.UserController.create.response" }
  ],
  "$defs": {
    "demo.UserController.create.request":  { ...Schema,不带 $schema... },
    "demo.UserController.create.response": { ... }
  }
}
```

合集本身是合法的 2020-12 Schema 文档(顶层没有约束关键字,`$defs` 里的每个定义可用 `#/$defs/<名字>` 引用)。没有请求/返回模型的接口,`x-csap-operations` 里对应的项为 `null`,`$defs` 不放。`$defs` 的名字 = `operationId + ".request" | ".response"`;JSON Pointer 里 `~` `/` 要转义,key 里一般只有 `.`。

接口顺序 = 文档里的顺序。`method` 取 `methods[0]`(为空取 `GET`);`path` 按 2.2 第 1 步拼接,保留 `{name}`。

### 4.3 单个接口的 Schema

**返回(`response`)**:取 `response[0]`(同 2.3):`OBJECT`/`T_OBJECT` → 对象 Schema;`ARRAY` → `{"type":"array","items":对象 Schema}`;`BASE_DATA` → 按 `name` 的标量 Schema。

**请求(`request`)**:请求不是一个整体,按**位置**分区,固定为这样的对象(只含有字段的分区):

```json
{ "type": "object",
  "properties": { "path": {...}, "query": {...}, "header": {...}, "form": {...}, "body": {...} },
  "required": ["path", "body"] }
```

字段所在分区:`paramType` = `PATH`→`path`,`QUERY`→`query`,`HEADER`→`header`,`FORM`/`FORM_DATA`→`form`,`BODY`→`body`;`DEFAULT`(或缺省)按方法:`GET`/`DELETE`/`HEAD`→`query`,其他→`body`。遍历 `request` 里**所有**模型(含 `BASE_DATA`)的所有字段,隐藏字段跳过。分区内是对象 Schema;若某个 `modelType=ARRAY` 的请求模型的字段落在 `body`,则整个 `body` 是 `{"type":"array","items":对象 Schema}`(该模型的字段做元素)。分区自己有必填字段时,才出现在外层 `required` 里。

### 4.4 字段 → Schema 的映射

对象 Schema:`{"type":"object","properties":{按文档顺序},"required":[必填字段名]}`(没有必填字段时不写 `required`)。字段 Schema:

**类型**(按 2.5.2 的 kind):

| kind | Schema |
|---|---|
| `integer` | `{"type":"integer","format":"int32"}`;`long`/`int64`/`biginteger`/`atomiclong` 用 `"int64"` |
| `number` | `double`/`float64`/`number` → `"format":"double"`;`float`/`float32` → `"float"`;`bigdecimal` 不写 format |
| `boolean` | `{"type":"boolean"}` |
| `date` / `datetime` / `time` | `{"type":"string","format":"date" / "date-time" / "time"}` |
| `array` | `{"type":"array","items":元素 Schema}`;有子字段时元素是对象 Schema |
| `object` | 有子字段 → 对象 Schema;否则 `{"type":"object"}`(`modelType` 为 `OBJECT`/`T_OBJECT` 且类型名不认识时同样当对象) |
| `string`(含自定义类名) | `{"type":"string"}` |

嵌套超过 12 层:对象写 `{"type":"object"}`,数组写 `{"type":"array","items":{"type":"object"}}`。

**元数据**:

| 文档字段 | Schema 关键字 |
|---|---|
| `description`,为空时用 `value` | `description`(仍为空则不写) |
| `example`(非空,且 Schema 类型是 string/integer/number/boolean) | `examples: [值]`,按类型转换,转换失败用原字符串 |
| `defaultValue`(同上) | `default` |
| `required: true` | 写进父对象的 `required` |
| `keyName`(字段的规则键,如 `request.name`) | `x-csap-key`(导入时用,见 5) |
| `validate` 不为空 | `x-csap-validate`:原样保留每条 `{type,pattern,message,code,level}`(空值省略),**无损**,导入优先读它 |

**校验规则 → 标准关键字**(`type` 忽略大小写;作用在字段自身的 Schema,数组字段作用在数组层;不适用的类型忽略,但仍保留在 `x-csap-validate` 里):

| 校验 type | 条件 | 关键字 |
|---|---|---|
| `NotNull` | — | 无(必填已由 `required` 表达) |
| `NotEmpty` / `NotBlank` | string | `minLength ≥ 1` |
| | array | `minItems ≥ 1` |
| | object | `minProperties ≥ 1` |
| `Length` / `Size` | string | `minLength` / `maxLength`(`pattern` 为 `"最小,最大"`,`"n"`=恰好,`"n,"`=无上限) |
| | array | `minItems` / `maxItems` |
| | object | `minProperties` / `maxProperties` |
| `Min` / `Max` | integer、number | `minimum` / `maximum`(整数值写成整数) |
| `Pattern` | string,且 `pattern` 不以 `PATTERN_` 开头 | `pattern`;有多条时第一条写 `pattern`,其余各写成 `allOf` 里的 `{"pattern":...}` |
| `Pattern` | `pattern` 以 `PATTERN_` 开头(内置规则名) | 无标准关键字,只在 `x-csap-validate` 里(两种语言的内置正则表并不完全相同,先不翻译) |
| `Enum` | 任意 | `enum`:`pattern` 按逗号拆分、去空白,按字段类型转换后的值 |
| 其他(自定义校验类型) | — | 无,只在 `x-csap-validate` 里 |

多个规则落到同一个关键字时,下限取最大、上限取最小。没有 `Enum` 校验、字段是 string 且 `extendDescr` 非空时,`enum` = 各项的 `name`。

正则原样导出,**不翻译方言**(Java 正则、Go RE2、ECMA-262 在常见写法上兼容,差异写进文档提示)。

### 4.5 Schema 黄金样本

`cases/user-create.*`(路径变量 + 请求头 + 请求体里的必填/Length/Pattern/Min-Max/Enum/数组/嵌套对象/隐藏字段,返回带 `LocalDateTime`/`BigDecimal`)和 `cases/user-list.*`(`DEPRECATED`、GET 的 DEFAULT 参数落 `query`、`ARRAY` 返回)。验收:`python3 1.4.0-mock-golden/schema_reference.py --check` 通过;Java、Go 单测对 `*.method.json` 产生与 `*.schema.json` JSON 值相等的结果。

## 5. JSON Schema 导入

### 5.1 能导入什么,不能导入什么

文档的**结构**(有哪些接口、字段、类型、嵌套)来自代码,规则只能改"说明、必填、示例、校验"。所以导入的边界是:

- ✅ 把 Schema 里**已存在于文档的字段**的 `description`、必填、示例、校验,转成该接口的字段规则;
- ❌ 不创建接口、不创建字段、不改字段类型。Schema 里文档没有的字段,放进 `unmatched` 报告,不丢弃也不落库。

Mock 不需要单独的"从 Schema 导入返回结构":导入产生的 `example`、`enum`(枚举规则)、`Min`/`Max`、`mock`(见 5.3)已经能驱动 Mock 的取值;结构以文档为准。没有文档的接口不 Mock。这是有意的边界,避免出现"文档页和 Mock 返回两套结构"。

### 5.2 端点

`POST /csap/schema/import`(JSON body):

```json
{ "key": "demo.UserController.create",
  "kind": "request",
  "section": "body",
  "schema": { ... },
  "apply": false }
```

- `kind`:`request` 或 `response`。
- `schema`:`kind=request` 时,若是 4.3 的导出形状(顶层 `properties` 含 `path/query/header/form/body` 分区),按分区匹配;否则必须给 `section`,`schema` 当作该分区的对象 Schema。`kind=response` 时 `schema` 就是返回的 Schema。
- `apply`:缺省 `false`。`false` 只预览;`true` 才写入。

返回(外层沿用文档接口的统一包装):

```json
{ "key": "...", "kind": "request", "applied": false,
  "rules": { "request.name": { "description": "...", "required": true, "example": "...", "validate": [ ... ] } },
  "yaml": "<rules 按 method-field.yaml 的格式渲染的文本,可直接粘贴进规则文件>",
  "matched": 12,
  "unmatched": [ { "path": "body.nickname", "reason": "字段不在文档中" } ],
  "skipped":   [ { "path": "body.address", "keyword": "oneOf", "reason": "不支持的关键字" } ] }
```

**默认关闭**:`csap.apidoc.schema.import-enabled=false`(Go 同义 Option)。理由:这是"写规则"的端点,且导入的校验会在运行时生效(请求校验、返回过滤),必须显式开启。关闭时 `404`。开启后 `apply=true` 走现有的规则保存路径(DevTools 保存同一条路径),产生修改记录、版本号,受只读模式(`read-only: true`)约束——只读时 `apply=true` 返回明确错误,预览仍可用。

### 5.3 匹配与转换规则

**匹配**:每个 Schema 属性对应文档里一个字段。先看属性上的 `x-csap-key`(导出文件带的规则键),命中文档里 `keyName` 相同的字段;没有则按路径匹配:从分区根起的字段名连成 `a.b.c`,数组元素透明(`orders.orderId`)。匹配不上 → `unmatched`。

**转换**(每个匹配上的字段,没有对应关键字就不产生该项):

| Schema | 规则 |
|---|---|
| `description` | `description` |
| 在父对象 `required` 里 | `required: true`(**只会写 true**,不会因为"没列出"而改成 false,避免一次导入悄悄放宽或收紧大量校验) |
| `examples[0]`,或 `example` | `example`(转成字符串) |
| `x-csap-validate` 存在 | `validate` = 其原样内容(优先,无损) |
| 无 `x-csap-validate` 时的标准关键字 | `minLength`/`maxLength` → `Length "min,max"`;`minItems`/`maxItems` → `Size "min,max"`;`minimum`/`maximum` → `Min`/`Max`;`pattern` → `Pattern`;`enum` → `Enum "a,b,c"`。新生成的条目 `code`=`1001`、`level`=1、`message` 为空(沿用校验的默认文案) |
| `x-csap-mock`(导入端识别,导出不产生) | `mock`(用于手写 Schema 时直接给 Mock 值) |
| `default`、`format`、`$ref`、`oneOf`/`anyOf`/`allOf`(导出的 `pattern` 附加项除外)、`additionalProperties` 等 | 不支持,进 `skipped`,不影响其他关键字 |

导入对同一字段**整体替换** `description`/`example`/`validate`/`mock`/`required` 里 Schema 提供了的那几项;Schema 没提供的项保持原规则不变。

### 5.4 没有 apply 之外的批量入口

不做"导入整个合集文件"的端点:合集里有几十上百个接口,一次写入的影响面太大。需要批量时,逐个接口预览确认(UI 或脚本循环调用),或用迁移工具的 YAML 导出/导入(1.4.0 数据库模式已提供)走 Git 审查。

## 7. 需要主会话拍板的点

1. **入口用前缀 `/csap/mock/**` 而不是请求头**(2.1)。推荐前缀,固定、不可配置。
2. **默认种子固定为 `csap`(结果可复现)**,`seed=random` 才随机(2.4)。推荐固定:前后端联调、截图、测试都更稳。
3. **字段名启发式无开关、默认开启**(2.5.4;4 月稿是默认关)。推荐开启:否则 Mock 数据全是 `"string"`,联调体验差;想要别的值用 `example`/`mock` 覆盖。
4. **新增规则键 `mock` 和三个表达式 `@int`、`@oneOf`、`@uuid`**(2.6)。这会往文档 JSON 的 `Parameter` 加一个可选字段,并改规则模型(Java/Go 各一处)。如果不想动规则模型,可砍掉 2.6,只靠 `example`——但这样没法指定数字/对象/数组类型的固定值。
5. **导入的范围**(5):只更新已有字段的说明/必填/示例/校验,不建字段;默认预览,`apply` 需 `schema.import-enabled=true`;`apply` 复用现有规则保存路径。同意的话,Java 端 `apply` 取决于现有保存路径是否好复用,实现时如不顺,先交付"预览 + 返回 yaml",`apply` 留到 1.4.1,会在实现阶段回报。
6. **`mock` 字段进规则模型会碰到另一个 Java 会话的区域**(校验对齐在 `csap-validation-core`,字段库在新模块;规则合并代码两边可能都会读)。我会把改动限制在"透传一个字段"并优先提交,请 java-db 会话知晓。
7. **前端(`csap-apidoc-ui`)谁做**:Mock 预设环境 + 响应"Mock"标记 + 导出 Schema 的下载入口。前端 Java/Go 共用。我可以在 Java 会话里一并做(Node 20,纯增量),也可以由 docs/前端会话做;请指定。
8. **Number 类型**:Go 现有 OpenAPI 把 `Number` 当 string,与 Java 不同;本文要求新代码按 number(2.5.2)。go-db 不需要改旧的 OpenAPI 导出,但请知晓这个差异。
9. **文件命名**:黄金样本和 Python 参考脚本放在 `docs/design/1.4.0-mock-golden/`。如果希望 Go 测试用 `testdata` 副本,请 go-db 在测试里直接读这个目录,不要复制(避免两份漂移)。

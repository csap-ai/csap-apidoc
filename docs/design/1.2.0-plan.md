## A. Java 运行时模块

### 原实现(csap-framework-web)为什么不能直接搬

- 挂载方式是替换 `RequestMappingHandlerAdapter` 的返回值处理器和参数解析器,依赖 `ResultUtil`、`ApiResult`、Servlet 适配器等 csap-framework 的类。
- `JacksonFilterSerializer` 每次请求对共享 mapper `addMixIn`,线程不安全且被缓存后不生效。
- 规则每次请求现场生成过滤器,没有预编译。
- 可以沿用的是语义:`ApiMethodArgumentResolver` 的"先解析、再按顺序调用 `ApiMethodHandle`",以及 fastjson 按类型白名单/黑名单的过滤语义(Go 的 ModeCsap 就是照它复刻的)。

### 设计

- **Boot 2 / 3 共存**:只用 spring-web/webmvc 的抽象(`ResponseBodyAdvice`、`HandlerMethodArgumentResolver`、`MethodParameter`),不引用 Servlet 类;按 Spring 5.2 编译,javax / jakarta 问题自然不存在。顺手修 `ApidocClazzUtils` 只认 javax Servlet 类型的问题。
- **返回过滤(Jackson)**:
  - `CsapFilterIntrospector` + 每请求新建的 `CsapPropertyFilter`,由 `ResponseFilterAdvice` 把返回值包成 `MappingJacksonValue`。
  - 没有规则的接口完全不受影响。
  - 两种模式:`path`(路径白名单,与文档显示一致,与 Go 默认一致)、`csap`(按类型合并白名单/黑名单,兼容 csap-framework 的行为)。
- **规则与热更新**:`ResponseRuleRegistry` 预编译每个接口的规则,`ConcurrentHashMap` 整体替换;core 在扫描 / DevTools 修改后发布 `ApidocRulesRefreshedEvent`,只重建受影响的类。修 `ApiDocService` 先 `clear()` 再登记导致中途读到空规则的问题。
- **请求校验**:`BeanPostProcessor` 把参数解析器包成 `ValidatingArgumentResolver`,解析后调用 `ValidateIntercept`。模式 Off / Observe(记录、放行)/ Enforce(拦截);可按接口覆盖。违规记录走 SLF4J,有 Micrometer 时计数 `csap.validation.violations`。
- **全部默认关闭。**

### 配置

```yaml
csap:
  apidoc:
    runtime:
      filter:
        enabled: false        # 返回字段过滤
        mode: path            # path | csap
        engine: auto          # auto | jackson | fastjson
        endpoints:
          "[com.example.UserController.get]": off
  validation:
    mode: off                 # off | observe | enforce
    http-status: 200
    endpoints:
      "[com.example.UserController.create]": enforce
```

兼容:只写了 `csap.validation.enabled: true` 时等同 `enforce`。

### 验收

- Boot 2.3 / 2.7 / 3.2 × JDK 11 / 17 / 21 集成测试通过。
- 无规则接口额外开销 < 1%;有规则时过滤开销 ≤ Jackson 序列化耗时的 15%;10 条校验规则 p50 < 20µs。
- DevTools 修改规则后,下一个请求立即按新规则过滤 / 校验。

### 风险

- 开启校验会改变已有接口行为,所以默认关闭,先用 Observe。
- 同名重载方法共用一份规则(键是 `类名.方法名`),文档写明。

## B. Go v0.1.0

按 `csap-apidoc-go/docs/DESIGN.md` 的 M4、M5 执行;内嵌前端用 GitHub main 上 1.1.1 的构建。完成后通知使用方接入。

## C. 前端与遗留

- 暗黑模式:文档页与 DevTools,跟随系统并可手动切换。
- OpenAPI 导出:修 `required` 为 null 的空指针,注册为 Bean。
- JSON 策略写出真正的 JSON。
- SQLite:启动时检测旧表的 NOT NULL 约束并迁移。

## 已确定(2026-11-17)

- 过滤默认 `path` 模式;从 csap-framework 迁移的项目配 `csap`。
- fastjson 1 和 fastjson2 都支持。
- Boot 2 上 javax 校验注解 1.2.0 一起支持(原 `ValidateFilter` 只认 jakarta,会静默跳过 javax 注解)。
- 校验失败默认 HTTP 200 + `{code, message}`,可配置。

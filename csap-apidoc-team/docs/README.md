# CSAP Apidoc 团队版 文档

团队版是 CSAP Apidoc 的免费开源版本(Apache-2.0),企业自部署,面向多服务、多成员的团队。

## 它解决什么问题

开源版让一个服务在运行时拥有 API 文档和字段规则。服务多了、人多了,会遇到这些事:文档散在各服务里、谁都能改规则、改了没人知道、出了问题查不到是谁改的。团队版在开源版之上做"多人、多服务"的协作:

| 能力 | 说明 |
|---|---|
| 文档中心 | 汇聚所有服务(任何语言)的接口文档,跨服务搜索,看服务在线状态 |
| 成员与角色 | 组织管理员,项目里的维护者 / 开发 / 只读 |
| 修改单与审批 | 规则改动先写草稿,提交、审批、发布;并发修改有冲突检测;可回滚 |
| 审计 | 谁在什么时候改了什么,含服务侧直接修改和 MCP 调用;可查询、导出 |
| 通知 | 修改单、服务侧修改、服务离线,推送到企业微信、钉钉、飞书或自建接收端 |
| 多环境与推广(1.1) | 开发 / 测试 / 生产分别管理,对比环境差异,一键把规则推广到下一个环境 |
| 评论与编辑中提示(1.1) | 修改单上讨论;编辑规则时看到谁也在改、有哪些未完成的修改单涉及它 |
| 审计哈希链(1.1) | 发现绕过团队版直接改、删审计记录;提供独立校验脚本 |

## 与开源版的关系

- **开源功能不阉割。** 没有团队版,你的服务照常工作;团队版只加"多人、多服务"的部分。
- 团队版**直接读写开源数据库模式的三张表**(`{前缀}rule` / `{前缀}history` / `{前缀}meta`,默认前缀 `csap_apidoc_`)。服务(Java 或 Go)按开源版已有的版本号轮询,就能拿到团队版发布的变更,**不需要为团队版改业务代码**。
- 团队版自己的数据在同一个库里,表名以 `csap_team_` 开头。
- 多语言:文档中心汇聚的是各服务的 `/csap/apidoc` 接口,Java、Go 服务都可以接入。
- 服务自动注册需要开源 Java 1.5.0 / Go v0.3.0 起;更早的版本可以手工添加。

## 快速开始

1. 准备一个与你的服务**共用**的数据库(MySQL 或 PostgreSQL),按 [install.md](install.md) 启动团队版。
2. 浏览器打开团队版,完成初始化(创建组织和管理员)。
3. 建项目,加成员。
4. 创建 `REGISTER` 令牌,按 [connect-services.md](connect-services.md) 让服务注册上来(或手工添加)。
5. 在文档中心查看文档;在规则页发起第一张修改单。

## 后续版本

多环境与推广、修改单评论、编辑中提示、审计哈希链在 **1.1**(开发中,未发布)提供,文档已先行写好,标注"(1.1)"。以下功能计划更晚的版本:按环境的细粒度权限、SSO(OIDC / LDAP)、API 监控、AI 辅助、评论 @ 提醒与邮件通知、多实例部署。

## 版本与已知限制

- 只支持单实例部署(1.1 的"编辑中提示"同样存在进程内存里)。
- 达梦 DM8、人大金仓**未在真实库验证**,请先在测试环境验证。
- 没有 SSO 和多因素认证。
